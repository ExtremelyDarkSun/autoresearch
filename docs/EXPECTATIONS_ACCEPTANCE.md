## 如何读状态

- **本地实现**：有可调用机制及本地测试支持；只证明该机制，不证明真实宿主部署或完整流程。
- **部分**：同一要求中仅部分行为实现，或函数存在但实际入口未接。
- **缺失**：未找到该要求的可用实现。接口、模板、同名文件不算完成。
- **仅规则 / 语义纪律**：前者是可实现但当前只有契约；后者需 agent 或人判断语义，不能用字段齐全证明。
- **宿主相关 / 未联调 / 未验收**：需要真实宿主、通道或独立会话证据；不计为通过。
- **已退役 / 历史记录**：保留源编号作追溯，不恢复旧私有状态，也不拿历史结论当当前验收。

## 补齐顺序与完成判据

1. **先补研究执行主链**：完整事前材料与来源版本、实际 argv/实现声明、统一启动检查、前轮复盘与历史运行防补造、结束事件和安全停机。用会调用真实子进程的合成评测器验“不合格时一个子进程也不启动”。
2. **补报告与独立核验**：完整 scribe 供料、页面来源/正文摘要/作者/事件截止回执；监控原话快照、完整 JSON、轨迹、意见与跨报告阻断、证据变更失效；宿主核验 spawn/fork、真实消息与读事件。各做篡改、缺失、陈旧和合理探索正负例。
3. **补审批与入向**：中性决策对象、六块 HTML、附件先于卡、同决策双回执、两小时取消；通道客户端保留在部署适配层。入向订阅、受管盯梢、回复超时与叫醒。用假通道验状态机，再用配置后的真通道验送达和回复。
4. **补持续推进与远端进度**：goal 状态接入、单一推进来源、远端声明式采集、失败事件、受管唤醒与重挂、无事窗口退避。厂商信息与比赛字段放配置，不写死在内核。
5. **补初始化和完整冷启动验收**：从 clone + 空工作区开始，生成必要专题文档/配置引用/隔离运行环境，运行小样本、审批的大题单及安全并行、分析、scribe、下一轮和用户停止。验证时清楚区分合成离线、真实宿主、真实远端和真实通道。

全部适用要求有证据才可称“功能迁移完整”。源预期中语义纪律的验收可由 agent 主动完成，无需强制全改成脚本；但必须有原始材料与完成记录。通道、机器及比赛资料需要部署配置，**缺少个人配置本身合理，缺少通用功能不能归为只需填写配置**。

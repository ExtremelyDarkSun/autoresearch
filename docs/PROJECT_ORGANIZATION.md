# 固定项目组织验收

[项目模板入口](<../project/AGENTS.md>)已经作为普通Git文件提供。组织抽取与原维护功能的对应见[映射](<../project/ORGANIZATION_MAP.md>)，来源版本只有[字节与哈希](<../project/organization-source-manifest.json>)，不复制实例数据。

## 迁入与适配

根共同规则、平台/实验/框架三层入口、多级原始资料目录、实验活件/历史边界、基线/运行/交接分工、问题冷件索引、读取图、维护登记和归档入口随clone提供。
所选内核契约与profile仍是仓库中的权威版本；初始化复制当时版本并重写本地链接，来源和结果分别留哈希。旧项目不自动覆盖升级。

为兼容公共工具，专题科学正文固定在根topics；中文实验分析目录只索引。代码、环境和状态仍在现有工具固定路径，不能仅为外观搬动。

## 找回的维护行为

- 修正公开维护规则中写反的J1：高频全文读取的追加台账是分层候选；读者固定不是免切理由。
- 恢复当前答案/行动依据/历史/原始证据四层，相关现行文档仍全文读。
- 规则按动作触发拆分、只有一份正文；索引写动作、直接落点与读取时机。
- 冷件跟随热件、按日期同日追加、保留原编号、双向指针、前后字节与哈希；冷件不是退休归档。
- 默认触发/上限保留60,000/80,000字节、400/600行、30/40条；保留锚与头部不计入滚动负载，到线不自动截断。
- 改前核真实工作树、保留历史包、不用HEAD冒充脏工作树；失败先对照改前版本。
- 子会话默认独立短任务包，不遍历全部索引；指定原文仍全文读，独立核证不能只看负责人结论。
- 实际读取路径必须测；文件存在、链接通过、agent自述都不证明宿主已注入。

## 独立会话的实际读取

独立只读会话从生成工作区根入口出发，经工具打开完整根规则、维护入口、维护正文、读取政策、加载图、基线名单、运行登记、工程未决/冷件索引、历史索引和归档入口。
它正确找到新建文件前的要求；区分“无基线”“无已验证运行”和“未登记”；按原编号找到冷件反查方式；识别历史AGENTS不能生效；识别子会话无需遍历全索引但指定原文仍须全文读。
反向提问“能否宣称宿主已自动注入全部规则”，回答不能，并指出静态检查与宿主证据的区别。机械负例另测断链、丢清单、越界路由。
这是使用工具沿入口阅读的验证，未测试实际新宿主的自动目录注入或预算丢弃行为。

## 测量与边界

生成项目所有路由入口合计8,847字节，路由required正文按项累加31,912字节（含跨路由重复）；这不是开局实际注入量，任务可能还需其他完整材料。
全量指令诊断重新测得：source 122,602字节，bundle 125,021字节，单份最大15,948字节，建议量156,276字节。诊断量与分层注入不能混用。

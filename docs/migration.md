# 迁移与拆分说明

这次交付是独立的新 Git 项目。原项目继续保留，新项目不读取原项目的数据库、实验目录、当前比赛配置或凭据文件。

**按完整行为预期验收，功能迁移尚未完成。** 本文的“保留机制”只描述局部抽取，不能外推整组行为已实现。具体缺失、入口未接线和部署未验证逐项见[109 项功能迁移验收](<EXPECTATIONS_ACCEPTANCE.md>)；验收依据见[中性化完整预期](<../kernel/contracts/framework_expectations.md>)。

|---|---|---|

| 当前题库、模型、真实轨迹、结果、历史报告 | 不迁移 | 属于研究实例；不得作为公开示例 |

## 为什么没有逐文件复制旧框架

旧文件有些包含通用机制、目标约束和实例事实三种内容。整份复制会把当前比赛绑进新框架。因此此次按函数、常量、协议、模板和规则段落拆分，并用独立测试检查接口。

旧框架里仍有一些历史工具没有逐字迁入：旧站点推进器、旧全套终点闸、已填满的分析与请求台账、赛事采集脚本、特定模型启动器、官方环境打包器，以及当前渠道的外发命令。对应的通用需求通过新事务内核、治理契约和显式适配接口承接。**这不表示旧工具的所有细节已逐项复刻。**

agent profile 的缺口逐项列在 `profiles/agent-harness/EXTRACTION.md`。例如，依赖真实 gold 补丁的判据、官方沙箱环境和特定评分钩子仍须比赛接入时提供；默认仓库不具备这些资料。

## 机械检查和宿主接线的区别

| 能由本地代码检查 | 仍需真实部署验证 |
|---|---|
| 数据库事务、版本冲突、追加事件 | 远端实际隔离、权限和运行环境 |
| 同请求幂等、结果字节与哈希 | 真实执行器是否支持按 request_key 去重及查询 |
| 计划结构、回归集合、审查版本绑定 | 审查者确实独立、原始宿主读证据真实到达 |
| 用户来源字段及触发节点是否齐全 | 来源事件的真实性与用户权限 |
| 完整指令文本的测量与包含核对 | 当前模型请求确实收到该文本 |
| 事件负责人绑定与模拟投递 | DSH 当前 profile 已加载、对应会话能被唤醒 |
| 模板八节、经验确认版本 | 科学结论是否成立、报告是否易读 |

治理方法已可调用，但它们不会自动截获任何外部程序。实际启动器必须先调用计划、审查与意图检查，再把授权、资源和任务凭据交给执行边界。当前通用 Runtime 不会替调用方猜测应使用哪个计划与意图。README 没有把“治理模块存在”当成“所有生产启动入口已接好”。

本次验收记录只描述执行过的离线检查；真实宿主、AutoDL 和正式评测环境均应在完成部署后另留实测记录。

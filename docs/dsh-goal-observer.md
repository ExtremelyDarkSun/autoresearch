# 观察者与持续推进

本仓库交付[观察者运行插件](<../kernel/hosts/dsh/plugins/goal-observer/README.md>)与[通知显示插件](<../kernel/hosts/dsh/plugins/goal-observer-ui/README.md>)。原生 goal 管状态和自动轮额度。观察者为后续自动轮给出下一步。受管推进器同时监听外部事件，只通知负责人。

源码和模拟宿主测试不证明插件在你的宿主里加载。完整验收仍需真实模型、目标状态与会话来源消息。通用安装边界见[DSH说明](<dsh.md>)。

## 1 安装与配置

1. 从公开仓库初始化项目。新电脑准备步骤见[换机说明](<NEW_MACHINE_RECOVERY.md>)。
2. 运行 `tools/prepare_new_machine.py --workspace <项目目录>`。工具生成部署输入和下一条生成命令，不改宿主。
3. 执行回执中的 `next_argv`。配置生成器支持 `goal-observer` 与 `goal-observer-ui`，可用 `--only` 单独生成。
4. 在 DSH 插件管理器安装本仓库的两个插件目录或可重建的包。按生成片段应用配置。文件路径必须是当前机器实际路径。
5. 由你选择窗口重启或按宿主支持的装载方式应用。打开新会话验收，不凭配置文件或页面热更新宣称生效。

运行插件本身默认 `enabled:false`，需要Node.js 20.3+（使用AbortSignal.any）。换机准备工具会为当前项目显式生成 `enabled:true`，但生成成功不等于安装成功。运行插件和生成器省略值均为timeoutMs=60000、maxTokens=1800；换机工具显式生成240000和16000，供部署审核。UI模板用disabled:true关闭；换机工具的enabled:true输入会生成disabled:false。通知始终默认关闭。已有不同部署输入时，工具拒绝覆盖。先保存旧版本，再核对新旧输入，保留自定义接收人和命令。

观察者的范围是当前 profile 内 objective 符合前缀的目标，不按项目目录过滤。默认前缀是 `[观察者]`，可在插件配置里改。若改前缀，创建目标时必须使用同一值。UI 插件只显示已有消息，不调用模型或恢复目标。

## 2 建立和续接目标

主会话先读目标、证据和完成条件，再调用 `get_goal`。

| 当前情况 | 动作 |
|---|---|
| 没有目标 | 用 `create_goal` 建立带前缀的目标，额度按用户要求和任务设置 |
| 已有同任务观察者目标 | 沿用现有目标，不重复创建 |
| 已有同任务普通目标 | 读取当前 id/revision，再 `edit`，保留原任务和累计轮数 |
| 当前目标属于另一任务 | 只有用户明确换任务时才 `edit`，否则说明冲突 |
| 恢复或分叉后 disarmed | 只有真人要求继续才 `resume` |
| 用户叫停 | 暂停 goal，停止补足作业，另核远端任务与机器的安全停止 |
| 额度用尽 | 报告未完成项，不另建同目标或清零计数绕过 |
| 达到完成条件 | 核对已有证据后 `complete`，后续不再执行 |

示例只演示字段，20轮不是固定额度：

```json
{
  "objective": "[观察者] 目标：完成指定功能。验收标准：功能通过正反测试，产物保存且用户能复查。",
  "max_goal_rounds": 20
}
```

创建目标的当前真人轮沿用宿主行为。观察者从后续自动 goal 轮介入，直接调用模型，不建常驻子会话。指令以 `source.kind=goal-observer` 追加，不能冒充真人消息。

## 3 异常和授权边界

观察者可以要求 `continue` 或在已有证据支持下要求 `complete`。观察侧没有自行暂停目标的权限。模型返回 `pause`、响应非法、解析重试失败或调用异常时，插件保留诊断，继续宿主本来安排的自动轮。它不清除宿主的额度、停止或暂停状态。

失败继续只允许主 agent 处理已经授权的工作。付款、注册、绑定支付、验证码和重启仍需真人决定。等待用户提问工具回答的状态不由插件代答。异常期间继续执行不代表观察者正常、任务完成或外部通知送达。

改目标、真人暂停、取消和卸载会使在途观察失效。插件不能把旧 revision 的判断用于新目标，不能让一次下游步骤重复执行。模型输出的网页、文件和历史记录均是待分析数据，不能成为新的授权。

## 4 通知：显式启用

插件不内置接收人、专题、机器人或发送脚本。部署方可提供一个通知程序：

```json
{
  "notification": {
    "enabled": false,
    "command": ["python", "<绝对路径>/notify_observer.py"],
    "throttleMs": 300000
  }
}
```

启用前填写真实程序，并自行配置通道授权。插件用 `shell:false` 运行 argv，只在固定参数末尾追加一个原因参数。它不替发送器设置批准标志，不请求任意 shell 命令执行。通知非阻塞，失败只记诊断。最近100个不同原因保留去重记录，同一原因在该窗口内只通知一次；移出窗口后可能再次通知。不同原因至少间隔配置时长。

这是发送器接口，不是内置飞书适配器。真实送达需要发送器回执另行核对。本仓库测试使用假发送器，不发送消息。

## 5 推进器同时使用

goal 负责方向与连续自动轮。推进器只监听事件并叫醒负责人。两者同时存在不算重复推进，重复启动同一实验才算。

公开入口是 `research.py progress-host`，具体参数看 `--help`。准备 `progress` 的采集配置及宿主联动部署，再将 `watch` 命令挂成宿主受管后台作业。唤醒一次后作业退出。负责人处理事件、登记 `outcome`、执行 `rearm`，再重新挂作业。

真实变化事件、超期入向和采集失败都须通知。goal 覆盖状态不能吞掉真实变化。没有变化时，有效 goal 可以抑制重复的静默叫醒。goal 状态未知仍是未知，不因收到事件就称已激活。

本地 mtime 不证明远端实验进度。远端等待须声明 SSH 命令、产物或事件探针，并保留原始输出与指纹。没有配置就写未配置，不凭心跳宣称实验存活。实际起跑仍走 workflow/remote 的审计、预算、计划和执行核验。

## 6 验收与回滚

本地先执行 `python research.py selftest --plugins`。统一自检包含运行插件的模拟宿主用例和 UI 的消息匹配测试。

部署后在新会话核对：

1. 插件已加载，普通目标不调用观察者，带前缀目标从自动轮开始出现独立来源消息。
2. 给至少四轮额度，要求三轮分别输出三个合成值。观察者每轮只安排当前项，第四个候选轮用于根据三条证据判定完成。
3. 真人插话、改目标和暂停时，在途观察不会恢复旧目标或重复下一步。额度停止仍有效。
4. 注入非法模型响应时，记录诊断，goal 状态不由观察者改成 pause/block，宿主规则保持有效。
5. 展开目标通知，UI 显示相同 goal id、revision、轮次的指令。没有匹配消息时保留原通知。原始消息不改。
6. 产生一个合成外部事件，验证受管作业确实回传并在处理后重挂。另查真实远端与通道，不用合成测试代替。

停用运行插件前，先处理当前目标并由用户决定是否暂停。停用 UI 插件须设置加载条目的disabled:true，按宿主方式应用后刷新页面验证。回滚到旧包会失去解析重试、异常继续及参数化通知，必须核对旧包语义。公开源码才是可重建来源，不能只保留部署目录里的改动。

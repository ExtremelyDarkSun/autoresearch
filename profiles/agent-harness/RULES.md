# agent harness 评测规则（必读）

> 这份文件被 `profile.toml` 的 `[instructions].required` 列为必读。
> 它只管一件事：**读这件事上的数，怎么算、什么算通过、什么算无效。**
> 它不含任何一场比赛的官方规则、指定模型或真实题号 —— 那些属于具体部署，不属于本 profile。

---

## 1 这个 profile 管什么

管：**题单 → 评测命令 → 结果 JSONL → 轨迹 → 对比**这条链上的接口与口径。

不管：harness 内部的 prompt、工具白名单、采样参数、模型选择。那些是**被优化的对象**，
住在被测仓库自己的配置里。本 profile 只负责「跑完之后怎么读数」。

判据：一句话里出现「这题为什么挂」「怎么改 prompt 更好」，那是被测对象的事；
出现「这次读数能不能和上次比」，才是本文件的事。

---

## 2 读数只有四种状态

| 状态 | 含义 | 算通过吗 | 进通过率分母吗 |
|---|---|---|---|
| `passed` | 评测判定这道题做成了 | 是 | 是 |
| `failed` | 评测判定没做成 | 否 | 是 |
| `infra_error` | 环境 / 依赖 / 服务侧的失败 | **否** | **否** |
| `timed_out` | 跑满预算被中断 | **否** | **否** |

⚠️ 后两种**既不算通过也不算失败**。它们表示「这次没测出 harness 的能力」。

通过率公式：`passed / (passed + failed)`。拿不到分母时它是 `n/a`，不是 0。

⛔ 三条禁令：

1. 不许把 `infra_error` / `timed_out` 说成「这题 agent 没做出来」。
2. 不许把它们从题单里删掉再报通过率 —— 删掉要写清删了几题、为什么，并且重算分母。
3. 不许只报一个百分数。必须同时报 `n`（真正计分的题数）与四态计数。

---

## 3 题单纪律

1. **一题一行，题号唯一。** 轨迹 / 补丁 / 测试输出通常按题号命名，重复题号会让后一次覆盖前一次
   ⇒ 「同一份题单里取两次读数」其实只拿到一份。要重复读数就**重复整轮运行**。
2. **空题单非法。** 0 行通常意味着命令行漏了参数，随后会静默跑成默认全量。
   ⇒ 读题单的函数会直接判错，不许「先跑起来再说」。
3. **不许删掉上次能过的题。** 要减题就整批换题单，并把它记成一次换尺，
   新旧读数不可直接比较。
4. 题单是**声明**，不是结果。声明了什么，就看实际跑了什么 —— 两者的题号集合必须一致，
   不一致时以落盘产物为准，并把差异写进报告。

---

## 4 测量配置：四个正交预算

| 预算名 | 管什么 |
|---|---|
| `per_task_minutes` | 这一题能持续多久（墙钟） |
| `max_tool_calls` | 这一题能对外部世界做多少次动作 |
| `max_turns` | 这一题能来回多少趟对话 |
| `command_timeout_seconds` | 单个动作能跑多久 |

四条互相独立，**不要合并成一个数**。任何一条变了，测量配置就变了。

⛔ 本仓库**不预填任何数值**，也不提供隐藏默认值：未配置就是未配置
（`limit_for()` 返回 `None`，`build_command()` 会拒绝发起评测）。

判据：两次读数只有在**题集相同 + 测量配置相同**时才能比。
`compare_results()` 默认硬查这两条；不满足就判「不可比」，不产出翻正翻负。

---

## 5 工作区与泄漏

1. **被测 agent 只能在自己的工作区里动作。** 绝对路径跑出 `allowed_roots` 就是越界。
2. **读到参考材料，这条读数作废。** 判「作废」不是「删掉」：保留原始产物，
   在报告里标注它为什么不能当「harness 能力」。
3. 轨迹检查只判 **agent 自己发出的动作**。工具返回里出现的路径不算 agent 的动作
   （否则 pytest 回显的系统路径会被误判）。
4. 敏感片段是**配置进来的**：参考补丁的独有行、隐藏测试名、答案目录路径。
   本仓库不预填任何一段真实内容。
5. ⚠️ 检查未配置 ≠ 干净。规则全空时判定是 `not_configured`，不是 `clean`。

---

## 6 默认没有官方评测环境

* 本 profile 的 `[evaluation].command` 默认是空数组、`configured=false`
  ⇒ 内核拒绝发起任何真评测。
* 本仓库**不附带**真实题库、gold、隐藏测试、官方评分脚本、指定模型权重。
* ⛔ 不许把本地读数说成「官方分数」，也不许把示例数据说成官方数据。
  写报告时用「本地读数」这个词，并写清题单与预算。

---

## 7 结果要落到哪

| 东西 | 位置 | 说明 |
|---|---|---|
| 结果 | `<output>/<result_file>` | 默认 `task_results.jsonl`，一行一题 |
| 轨迹 | `<output>/<trace_dir>/` | 默认 `traces/`，一题一个文件 |
| 测量配置 | `<output>/run_meta.json` 或 `<结果名>.meta.json` | 可选但强烈建议：写下当时的 `limits` 与 `measurement` |

没有 sidecar 时，事后对比只能拿 profile 现值当指纹；预算改过就会判「不可比」。
这是**故意的**：宁可判不可比，也不要拿两把不同的尺子做差。

---

## 8 改动纪律

1. 改 `profile.toml` 之后跑 `python profiles/agent-harness/checks/cli.py validate`，退出码必须是 0。
2. `[limits]` 只写通用预算名。写别的键会被判错 —— 这是为了不让某一场比赛的私有
   字段名或官方固定值混进通用配置。
3. ⛔ 不许把具体比赛名、指定模型、真实题号、gold 内容、历史读数写进本 profile 或本文件。
   要记这些，写到具体部署自己的目录里。
4. 命令模板只认 `{tasks}` 与 `{output}` 两个占位符，且**不经过 shell**。
   不要在模板里写 `;`、`&&`、`|`、`>` 这类操作符。

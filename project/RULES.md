# 项目共同规则

## 1.1 东西放哪

| 内容 | 固定位置 |
|---|---|
| 官方事实、公开资料、抓取方法 | `Kaggle平台/文档/`、`Kaggle平台/爬取过的资料/`、`Kaggle平台/tools/` |
| 平台运行与提交记录 | `Kaggle平台/实验/` |
| 实验规则、基线名单、运行登记和环境说明 | `AutoDL实验/实验记录/` |
| 分析与专题索引 | `AutoDL实验/实验分析/` |
| 具体专题的目标、假设、证据、报告 | `AutoDL实验/实验分析/topics/<专题>/` |
| 框架读取和操作导航 | `AutoDL实验/框架/` |
| 固定工具生成的代码、环境、状态 | `AutoDL实验/实验分析/worktrees/`、`AutoDL实验/实验记录/environments/`、`.autoresearch/` |
| 事前计划 | `AutoDL实验/框架/state/plans/`；专题内计划投影由工具维护 |
| 临时件、一次性脚本、候选稿 | `temp/` |
| 已退休且仍需留痕的材料 | `archive/` |
| 原始比赛数据、运行结果、凭据引用 | `data/`、`AutoDL实验/实验分析/results/`、`install/private/`；数据只读，凭据不入 Git |
| 将发往平台的包 | `submission/`；不能把当前包默认当作基线包 |

新增一级目录先说明为何现有二级不能容纳。没有硬性深度上限；避免重复根目录。
先查现有要求及未决问题，再新建。当前根目录只接受本表登记的内容和固定入口。

## 1.2 文件头与改前留证

维护文本含 `GENERATED-BY`、`LAST-EDIT`、`PURPOSE`、`ORIGIN`、`CUMULATIVE-DELTA` 五项。
JSON、外部原件、脚本产物和提交包按各自格式处理，不为加头破坏协议。
修改前查看该文件 Git 状态；工作树与 HEAD 不同就先保存实际字节，不能用 HEAD 冒充改前件。
改前件核对字节与哈希，记录替代路径。普通保留版本不额外请求审批；彻底删除或主动遗忘须用户授权。
修改时更新日期和累积差异；标签存在不证明内容已经同步。长头部历史移入有双向链接的历史文件。

## 1.3 安全与授权

不停止承载会话的宿主。删除前取得授权；归档保留来源。凭据只存私有引用，不打印值。
小样本在已授权共享预算内自主推进。大规模测试先送达 HTML 并等明确批准。线上提交逐次批准。
用户说停立即执行安全停止；报告失败不能阻挡停止。无回复、超时、机器未响应均不是批准或已停止证明。
仅授权、安全、执行真实性与重大研究缺陷构成研究阻断；写法与普通手续作提示、自查，不扩成新审批。

## 1.4 证据与数值

结论区分【官方】【实测】【读码】【推断】【未验证】。转述不升级为官方，读代码不冒充实测。
数字携带产生时间、样本、装置和适用条件，回到原始来源核对。未知写未知。
本地结果不能直接外推平台得分。正结果、负结果和被推翻的结论都应进入下一轮判断。

## 1.5 入口不放漂移状态

入口只写做什么、依据在哪、具体值去哪查。机器身份、端口、版本、费用、分数和当前进度放各自正文。
索引的描述与分册分量对应，常查大分册列到节；不把会漂移的计数写成固定事实。

## 1.6 表达与改写

沟通正文在[根入口](<AGENTS.md#和用户说话>)，不再复制第二套。
改动说明先说改了什么，再说它解决哪个问题及验证结果。不得把可能改成确定，不补原文没有的事实，不丢条件。

## 1.7 分层与索引

改行为的共同规则住本文件；知道事实的资料住平台线；跑实验的规则住实验线。线专属约束跟线走。
每条现行规则只有一个正文。索引必须写动作、直接落点、读取时机；不得经另一张索引猜规则。
搬迁必须更新所有入口及程序依赖，保留旧路径到新路径的对照。编号不重用、不重排。
维护细则直接读[文档维护正文](<../kernel/contracts/doc_maintenance.md>)。

## 1.8 维护顺序

查要求 → 核工作树与留证 → 最小修改 → 同步受影响入口与机读清单 → 相关校验 → 记录变化与未验证边界。
先检查失败是否改前已有，不能因既有失败回滚正确改动。实际读取验证不同于链接检查，不能混称通过。

# 三层结构填满后长什么样

虚构专题：`acme-pipeline` 的「把批处理耗时从 41 分钟压到 20 分钟以内」。

## 一、三层各放什么（同一件事的三个切面）

| 层 | 实际文件 | 里面写什么 |
|---|---|---|
| 大纲 | `topics/batch-time/TOPIC.md` | 目的：「批处理单次 ≤20 分钟」· 三条假设与判词 · 完成条件 |
| 大纲 | `topics/batch-time/STATUS.md` | 现在到哪：H2 已证、H3 未跑 · 下一步验什么 |
| 细节 | `runs/0007/plan.json` | 这一轮怎么跑：改 3 个文件的哪几行、对照是谁、门槛多少 |
| 细节 | `runs/0007/NOTES.md` | 跑的时候发现分块大小有个反直觉的上限 |
| 机器账 | `runs/INDEX.md` | 0007 \| 机器 A \| 14 题 \| 22.4 min \| 花费 1.2 单位 \| 结果文件 |

**判据**：把 `STATUS.md` 删掉，人还能回答「现在到哪」吗？不能 ⇒ 它是大纲，位置对。把 `runs/0007/NOTES.md` 删掉，会影响判断吗？只会少一条线索 ⇒ 它是细节，位置对。

## 二、五格台账（一页看懂边界）

| 格 | 内容（虚构） |
|---|---|
| 目的与假设 | 「≤20 分钟」+ H1 换分块器 / H2 并行两段 / H3 减少落盘次数 |
| 现状 | 给看的人：3 行结论；给 AI 的人：8 节研究页（目标 · 假设 · 设置 · 观察 · 解释边界 · 未决 · 证据） |
| 数据账 | `EVIDENCE_2027-03-04.md`：每个数一行，带产生时间 · 前提 · 条件 · 复算命令 |
| 待定与未决 | 「H3 要不要在低配机复测」—— 在等机器，已登记到等待簿 |
| 流程状态 | 只有机器写：上一次跑是 03-04 22:10，退出码 0 |

## 三、一个写错层的反例（真实高频）

**错法**：把「这一轮为什么选 14 题」写进了 `TOPIC.md` 的目的段。

```
❌ TOPIC.md §1 目的
   把批处理压到 20 分钟以内。本次选 14 题是因为 0006 里第 9 题超时、
   第 12 题缺输入，所以剔掉了……
```

**为什么错**：那段只对 0007 这一轮成立。下一轮换题单，它就成了错的废话，而它还留在「目的」里 —— 读的人以为这就是目的。

**改法**：

```
✅ 工作区 §1 目的：把批处理单次耗时压到 20 分钟以内（不涉及题单）
✅ 0007 计划文件：本轮题单 14 题；剔除 0006 的第 9、12 题，原因见 NOTES
```

判据一句话：**「这句话下一轮还成立吗？」** 不成立 ⇒ 它不属于大纲层。

## 四、跨专题资产挪位的例子

「分块器选型结论」被三个专题引用 ⇒ 它不该住在 `topics/batch-time/`。

```
挪出：topics/batch-time/MECHANISMS.md  →  实验分析/MECHANISMS.md
原位：留一个三行存根（已移到哪 / 为什么移 / 旧相对路径怎么跳）
登记：进必读清单，编号 R 系
```

⚠️ 不留存根的后果：三个月后旧计划文件里的相对路径静默断掉，没人发现，因为没有人会去点它。

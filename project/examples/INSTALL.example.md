# 复现清单填写样例（全占位符）

## 一、填写前先认清三条边界

1. **本机事实不入仓库**：机器名、端口、token 路径、绝对路径一律写进本机私有配置
2. **占位符必须写成能一眼认出的形状**：`<...>` 包起来，不要写成像真值的假值
3. **每条命令都要有「期望结果」**：没有期望结果的命令，装没装成只能靠感觉

## 二、清单本体（照着填）

| # | 动作 | 命令 / 位置 | 期望结果 |
|---|---|---|---|
| 1 | 装运行时 | `<语言> <版本> 或以上` | `<版本命令>` 打印 ≥ 期望版本 |
| 2 | 取框架仓库 | `<仓库地址>` → `<本地路径>` | `<本地路径>` 存在且 `git status` 干净 |
| 3 | 建工作区 | `init --workspace <目标目录>` | 目录**尚不存在**时才成功；已存在应报错 |
| 4 | 结构自检 | `layout-check --workspace <目标目录>` | 退出码 0，且**逐条**列出已被检查的路径 |
| 5 | 组件自检 | `selftest --plugins` | 退出码 0；记录插件数与断言数 |
| 6 | 恢复私有包（仅旧工程） | `<私有包路径>` → `<目标目录>` | 解包后文件数与清单一致 |
| 7 | 逐项验收 | 见下节 | 每项都要有「可核的东西」，不是「看起来对」 |

⚠️ 第 3 条是最常被忽略的：`init` 建的是**空库**，用它覆盖旧工程会当场丢掉实验记录。

## 三、逐项验收怎么写才算数

```
❌ 「装好了，能跑」
✅ 「selftest --plugins 退出码 0；Python 项 <N> 个（<通过> 通过、<跳过> 跳过），插件断言 <M> 条；
    运行库为空；14 条必读路径全部存在」
```

判据：**别人拿着这一行，能不能在一个新环境里复现出同样的判断？** 不能 ⇒ 它只是自我安慰。

## 四、本机私有配置长什么样（不入仓库）

```
# 只在本机存在，仓库里不出现
<机器别名>
<连接端口>
<凭据文件路径>
<绝对路径前缀>
```

⚠️ 凭据只存**引用**，不存值。检查办法：全仓库搜一遍凭据字段名，命中数应为 0。

## 五、恢复失败时的顺序

1. 先看**哪一步**的期望结果不成立（不是「哪一步报错」——有些步骤不报错但结果不对）
2. 再判断是**环境**问题还是**包**问题：用同一份包在干净环境重跑那一步
3. 仍然不成立 ⇒ 记录「命令 · 实际输出 · 期望输出」三样，才算一条可提交的失败报告

⛔ 不要先改包。改包会把「装不上」变成「装上了但不知道哪里不一样」，问题更难查。

# 示例目录说明

这里每一份都是**合成数据**：项目名、路径、数字、日期全部虚构，与任何真实研究无关。

## 它们解决什么问题

`project/` 下的正文只讲**规则**。规则读完了，人还是不知道「一份合格的实例长什么样」。
所以每份正文配一个示例，只示三件事：

1. **骨架**：该有几节、什么顺序
2. **粒度**：一条写多细，多细算太细
3. **边界**：哪些东西看起来像、其实不该写在这里

## 怎么用

- 写新文档时，先读正文的规则，再照对应示例的骨架写
- 示例里**每一处具体值都要换掉**：项目名、路径、日期、数字
- 示例不是模板：真正可被程序校验的模板在 `../kernel/templates/`

| 示例 | 对应正文 | 示什么 |
|---|---|---|
| `AGENTS.example.md` | `../AGENTS.md` | 一份入口索引的完整骨架与粒度 |
| `RULES.example.md` | `../RULES.md` | 文件头五要素的真实写法 + 三种常见写错 |
| `DOC_DESIGN.example.md` | `../DOC_DESIGN.md` | 三层结构填满后长什么样 + 一个写错层的反例 |
| `DOC_MAINTENANCE.example.md` | `../DOC_MAINTENANCE.md` | 一份台账从 300 KB 滚成热件 + 冷件 + 索引的前后对照 |
| `INSTALL.example.md` | `../INSTALL.md` | 新机器复现清单怎么填（只用占位符） |

⚠️ 示例里的「示例项目」叫 `acme-pipeline`（一条虚构的样本清洗流水线），它不存在。看到这个名字就知道是合成内容。

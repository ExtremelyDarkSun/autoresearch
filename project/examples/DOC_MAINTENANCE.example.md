# 滚动前后对照（虚构台账）

## 一、滚动前：一份 300 KB 的台账

```
runs/LEDGER.md          301,442 B / 2,180 行
  §1  … §148            每节记一次运行：改了什么、读数、判词
  ↑ 每加一节都要回读一遍全文、核对上一节编号、算一次哈希
```

**病因**（对应维护规则里的 J1/J2/J3 三条判据）：

| 判据 | 这份台账 |
|---|---|
| J1 每轮都被通读吗 | ✅ 是，加一节就得通读 |
| J2 有结案态吗 | ✅ 有：每次运行跑完即结案 |
| J3 增长是追加还是反复改旧条目 | ✅ 追加为主 |

三条都过 ⇒ 该滚。

## 二、滚动后的形态

```
runs/LEDGER.md                    38,900 B / 286 行   ← 热件
runs/LEDGER_cold/
    2027-02-11.md                 84,210 B            ← 冷件（按天）
    2027-02-18.md                 97,004 B
    2027-02-25.md                 81,328 B
    INDEX.md                       2,240 B            ← 编号 → 冷件 反查表
```

**热件顶部必须有的指针**（少这一块等于静默失忆）：

```
> 已滚出：§1–§120 ⇒ ./LEDGER_cold/，反查表见 ./LEDGER_cold/INDEX.md
> 冷件仍在被引用，不是退休归档；按编号去 INDEX 反查，不要以为编号记错了。
> 滚动日志见 ./LEDGER_cold/INDEX.md §滚动历史。
```

**每份冷件顶部必须有四样**：

```
来源热件：runs/LEDGER.md
覆盖编号：§1–§48
滚动时刻：2027-02-18 21:40 +08:00
滚动前热件 sha256：8f3c…（虚构）
```

## 三、INDEX.md 的形态（两列就够）

| 编号 | 冷件 |
|---|---|
| §1–§48 | `2027-02-11.md` |
| §49–§96 | `2027-02-18.md` |
| §97–§120 | `2027-02-25.md` |
| §121–§148 | 仍在热件 |

有反查表，**旧编号永远还能按编号找到** —— 这就是「编号不重用、不重排」能成立的前提。

## 四、四条最容易被做错的

1. **到线就去滚，不许「下轮再说」。** 没有上限的规则必然漂（实测过：一份台账四天涨了 46 倍）
2. **切割面只落在「已结案」上。** 「部分解决」「仍被别条引用」的连同上下文留在热件 —— 切走一半比不切更坏
3. **冷件是证据，⛔ 一个字都不许改。** 发现冷件写错了 ⇒ 在热件里加一条更正并指回冷件的行号
4. **冷件不进 `archive/`。** `archive/` 的语义是「不用了但要留痕」；冷件**还在被引用**，性质不同

## 五、这不是「自动截断」

⛔ 到线不是丢尾部。丢尾部就是**静默失忆** —— 读者看到的是「历史只有这么多」，而真实历史更长，且没有任何标记。
✅ 到线是**去滚**：搬到同级冷目录、写索引、写双向指针。

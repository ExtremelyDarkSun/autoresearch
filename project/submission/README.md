# 提交包

本目录是**将发往平台的包**的固定落点。⛔ **不能把当前包默认当作基线包**：基线是谁由[基线名单](../AutoDL实验/实验记录/BASELINES.md)裁定。

## 1 包内文件清单

> 一行 = 一个进包文件。第 1 行是**模板行**（尖括号内为占位），⛔ 不得当真实文件读。

| 文件 | 作用 | 参与评分 | 字节 | sha256 | 备注 |
|---|---|---|---|---|---|
| `<相对路径>`（占位示例） | `<配置 / 提示词 / 技能 / 工具>` | `<是 / 否>` | `<n>` | `<sha256>` | `<改动注意点>` |

**清单纪律**

- **进包文件全列**：包括配置与技能；只列「主要文件」会让复现缺件。
- **⛔ 提交包不带文件头**：本目录下的文件按平台格式为准，不为加注改字节。
- **`参与评分` 列**必须填：平台不读的文件放进来只会增加体积与混淆。

## 2 冻结（每次提交一次性动作）

| 步 | 做什么 | 失败的后果 |
|---|---|---|
| 1 | 列清单并逐个记 sha256 与字节 | 没清单 ⇒ 事后无法证明「交的是哪一版」 |
| 2 | 打包，记 **zip 的 sha256、字节、条目数** | 没有包指纹 ⇒ 平台结果无法归因 |
| 3 | 核对「冻结件 = 实际打包的件」 | 不同源 ⇒ 读数与提交对不上，且**不报错** |

⚠️ 冻结失败**不要开机、不要提交**。
⚠️ 拿到平台结果后要能说出「这个分数对应哪一份包指纹」；说不出就说明冻结没做好。

## 3 提交前验证

| 项 | 判据 | 记录 |
|---|---|---|
| 配置合法性 | 按官方规范逐项验，全通过才算过 | 通过 / 警告 / 失败计数 |
| 包结构 | 必须的入口文件存在，多余文件已清 | 清单对照结果 |
| 与基线差异 | 逐文件对照，写清「除改动点外逐字节相同」 | 差异文件列表 |
| 凭据与私有件 | ⛔ 不得出现在包内 | 扫描结果（命中的话说明扫了什么） |

## 4 平台结果

平台结果**回读到[平台实验索引](../Kaggle平台/实验/INDEX.md)对应节**，本文件不重复记分数。
本文件只留一行指针：`<提交次数>` → 该节号 + 包 zip sha256。

# 外部来源索引

按来源区分官方讨论正文、参考代码与原始抓取。**每一条外部说法都要能追到这里的某一行**。

## 0 分区

| 子目录 | 装什么 | 本索引怎么指 |
|---|---|---|
| `discussions/` | 讨论区话题、楼主正文、回复 | 按话题登记，见 `discussions/INDEX.md` |
| `ref_kernels_all/` | 公开参考代码（notebook / 脚本）原文 | 按 slug 登记，见 `ref_kernels_all/INDEX.md` |
| `raw/` | 抓取批次的原样返回 | 按批次登记，见 `raw/INDEX.md` |
| `references/` | 与主要原件对应的备份快照 | 按备份关系登记，见 `references/INDEX.md` |

## 1 来源登记表

> 一行 = 一个可引用的外部对象（一个话题、一份代码、一次抓取批次）。第 1 行是**模板行**（尖括号内为占位），⛔ 不得当真实来源读。

| 来源类别 | 原始地址（URL） | 取得时间 | 版本 / hash | 原件路径 | 派生件 | 权威程度 | 可否引用 · 已验证 / 未验证 | 更正与版本关系 |
|---|---|---|---|---|---|---|---|---|
| `<官方发言 / 他人自述 / 参考代码 / 原始抓取>`（占位示例） | `<完整 URL>` | `<YYYY-MM-DD HH:MM +08:00>` | `<抓取批次或文件 hash>` | `<仓库相对路径>` | `<派生出的话题文件 / 速读版>`，无则「无」 | `<官方 / 他人自述 / 未署名>` | `<可引 / 仅线索>` · `<已验证 <方式> / 未验证>` | `<取代了哪一行 / 被谁更正>`，无则「无」 |

**填表四条硬要求**

1. **URL 必须能点开且指向那一版**：只写站点首页不算来源。
2. **取得时间必须带时区**；同一地址不同时间抓到不同内容 ⇒ 各占一行。
3. **版本 / hash**：原始抓取写文件指纹；网页写抓取批次或页面版本标识。
4. **可否引用**只给两档：`可引`（有原文且已核对）/ `仅线索`（只有转述、二手总结、或未核）。**他人自述一律不是实测。**

## 2 读取纪律

- **只读原件**；要改就落派生件，⛔ 不覆盖原件。
- **重复备份不重复统计**：同一份内容的备份在 `references/` 登记「重复关系」，⛔ 不当成两份证据。
- **抓取完整性**：按接口返回的总数校验「抓到多少 / 共多少」；不完整就写进 `raw/INDEX.md` 的完整性列，⛔ 不拿不完整数据做结论。
- **同一说法多来源**：以发起方（官方/主办方）原文为准，其余作旁证并写明差异。
- **引用格式**：外部结论必须带「来源行 + 原件路径」，⛔ 不写「论坛有人说」。

## 3 空态

第一批材料进来时按顺序做：原件落 `raw/` → 正文落 `discussions/` 或 `ref_kernels_all/` → 本表加行 → 对应子索引加行。

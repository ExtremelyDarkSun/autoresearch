# 研究资料

解包源码、参考实现、速读版与独立分析按来源分目录；**原文与结论分开**。

## 1 分区职责

| 子目录或文件 | 装什么 | 生成方式 | 能否重跑 |
|---|---|---|---|
| `_whl_*/` | 解包的 wheel 源码（按包名一目录） | 解包脚本 | 可（同版本 wheel 解出来应逐字节一致） |
| `_nb_md/<slug>.md` | 参考 notebook 的**全部 markdown cell**（去代码的速读版） | 抽取脚本 | 可 |
| `_summary_shards/*.md` | 分片摘要的**原始产物**（保留不删） | 分片流程 | ⚠️ 不可逐字重跑，只留档 |
| `_inventory_*.jsonl` | **确定性清单**：一条一对象，字段由 probe 确定 | 清单脚本 | 可（字段名不许猜） |
| `_forum_manifest.jsonl` | 话题 → 原文文件 + 正文完整性校验结果 | 抽取脚本 | 可 |
| 其它 `*.json` / `*.py` | 单次探测的产物与校验脚本 | 一次性 | 视脚本而定，表里写清 |

**分工原则**：确定性内容（体积、作者、字段、计数、覆盖度）**全部脚本化**；
人读的一句话、标签、建议由分析产出，⛔ 不把可复现的数字写成人判。

## 2 清单文件的字段（推荐）

> 新增一类清单时，字段先 probe 出真实键名再写，⛔ 不许按想象定字段。下面各列至少要有：

| 字段 | 含义 | 例 |
|---|---|---|
| `id` | 稳定标识（不随文件名变化） | `<话题号 / slug>`（占位示例） |
| `path` | 原文在仓库内的相对路径 | `<相对路径>`（占位示例） |
| `bytes` / `sha256` | 体积与指纹 | `<n>` / `<hash>`（占位示例） |
| `fetched_at` | 取得时间（带时区） | `<YYYY-MM-DD HH:MM +08:00>`（占位示例） |
| `source` | 原始地址或接口方法 | `<URL / RPC 方法名>`（占位示例） |
| `integrity` | 完整性校验结果 | `<完整 / 缺 N / 未核>`（占位示例） |

## 4 纪律

1. ⛔ **摘要不替代原文**：分片摘要只回答「值不值得读」，读结论前回原文。
2. ⛔ **重跑会覆盖生成物**：脚本产物重跑前先确认没有别的写者；覆盖式产物**不写人工注释**（注释会被冲掉），要留说明就写在本 README 或另起 sidecar。
3. ⛔ **不把解包源码当本仓库代码**：它只作研究材料，不参与构建、不进提交包。
4. 分片摘要**保留原始、不删**：汇编时按片核对覆盖度，发现缺片先补再编。

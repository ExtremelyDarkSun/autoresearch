# 跨专题机制清单

> **这一页解决一件事**：有哪些机制、各自改善哪个**过程指标**、什么条件下值得用。它**只讲机制**，不讲某一次跑出了什么。
> **这不是台账**：读数、通过数、判词条件都在专题自己的 `TOPIC.md` · `EVIDENCE_<日期>.md` · `plans/<实验号>.json`；本页只收「换一个专题还成立」的那一层。
> **为什么放这里**：一份东西如果别的专题也要用，它就不属于任何一个专题 —— 所以它住在 `AutoDL实验/实验分析/`，⛔ 不住 `topics/<专题>/`。

## 0 怎么用（四条）

1. **一条机制一行**，只写下面五列；写不下就是这条机制还没想清。
2. **结论只取两档**：`成功` = 有实测、且同一方向被两次以上独立运行看到（或读源码结论与磁盘复现对得上）；`未判` = 只观察到一次，或只有推断、根本没跑过。⛔ 没有第三档，⛔ 不写通过数、分数与耗时原值。
3. **证据必须指到原始文件**（`EVIDENCE_<日期>.md` 的 `E<号>`、`plans/<实验号>.json`、复盘节号）。本页不复制读数；指不到就写 `未判`。
4. **不适用必须写清**：只写「什么时候该用」而省掉「什么时候别用」，下一个人会照抄；⛔ 把一次失败写成整个方向失败，也⛔ 把「没看到差别」写成「一样好」。

## 1 字段（每条一行，五列）

| M 号 | 机制（一句话） | 改善哪个过程指标 | 适用与不适用 | 结论与证据 |
|---|---|---|---|---|

- **M 号**只增不复用；改判据不换号，改机制本身才换号。
- **改善哪个过程指标**写具体那一项（例：减少空补丁 / 缩短定位耗时 / 降低撞墙率 / 让判读不错位），⛔ 不写「提升效果」这种空话。
- **结论与证据**两格合一：先写档（`成功` / `未判`），再写指针；一条一行，不写正文。

## 3 与专题的分界

| 放这里 | 放专题 |
|---|---|
| 换一个专题仍然成立的机制与适用边界 | 某个专题本轮的路线、判据、设置与逐题结果 |
| 两档结论 + 原始证据指针 | 读数正文、逐题配对、运行日志 |
| 一条机制的「什么时候别用」 | 该专题的停止条件与未验证前提 |

机制在专题里第一次出现时，正文留在专题；只有当「下一个专题也要用」时才在这里补一行，并在专题那次动作旁留指针。

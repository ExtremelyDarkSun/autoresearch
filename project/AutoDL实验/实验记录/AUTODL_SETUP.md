## 1 开机 / 关机

### 1.1 工具有哪些

| 件 | 用途 | 位置（引用，不含口令） |
|---|---|---|
| 开关机脚本 | `list` / `status` / `power_on` / `power_off` | `<路径>` |
| API 文档 | 重新拼脚本时的原始出处 | `<路径>` |
| 凭据缓存 | 登录凭证，有效期约 `<N>` 天 | `<路径>`（⛔ 只记位置） |

### 1.2 日常用法与状态值

```text
list                  # 列出全部实例与开关状态
status <机名>          # 查单台（输出行含 ssh -p）
power_on <机名>        # 开机，之后等 1–2 分钟才能连
power_off <机名>       # 关机
```

状态值：`running` / `shutdown` / `starting` / `stopping`。
匹配可用机名关键字、精确路径或 UUID。
⚠️ `status` 可能绕过管道打印实例口令：要捕获输出必须合并错误流，且**不要把输出落盘或贴进对话**。

### 1.3 关机的三种做法

| 做法 | 适用 | 验证 |
|---|---|---|
| 脚本 `power_off` | 日常 | 秒级后回读 `status=shutdown` |
| 容器内 `shutdown -h now` | 脚本坏了 | 下发给端口不可达的时间 |
| 驱动脚本末尾接关机 | 批量任务防空烧 | 落盘 `POWEROFF_SENT` 一类标记 |

⚠️ 容器内**没有开机能力**；开机只能走 1.2。
⚠️ **「没响应」不等于「已停」**：必须有一份回读证据，否则关机列写「未确认」。

## 6 成本与省钱

1. **跑完立刻关机** —— 计费只看开机时长，不看利用率；忘记关机不报错。
2. **本机能做的事绝不占机时**：读日志、解析结果、打包、跑本地闸。
3. **只传必需的**，上传带宽通常是瓶颈。
4. **传数据、装依赖可用无卡模式**，但切回可能抢不到卡。
5. **一次开机把多件事排满**，开机前把脚本、题单、清单准备好。
6. **批量任务末尾接自动关机**，防掉线空烧。
7. **不要盲目扩盘**：扩容关机也照收，用完要缩容。

## 8 凭据、授权与迁移纪律

| 项 | 做法 |
|---|---|
| 凭据 | 只记**引用位置**与有效期；⛔ 不记值，不写进日志、报告或提交包 |
| 授权 | 读工具预算账本；旧项目的口头授权、额度与白名单**不迁入**新电脑 |
| 机器信息 | 换机/重建实例后 UUID 与端口都会变，必须重测并覆盖 §0，⛔ 不许沿用上一台的数 |
| 提交包 | 与环境分开：环境版本变了要在 §3 记一条，⛔ 不要顺手改提交包来适配环境 |

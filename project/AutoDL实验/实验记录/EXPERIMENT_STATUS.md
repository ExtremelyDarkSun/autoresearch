# 逐实验状态台账

## 当前读取入口

> 维护核查日期：`<YYYY-MM-DD>`。以下是**记录完整度**的说明，不描述机器实时状态。
> 未登记的轮次**不等于**没有运行；缺行不能反推「没跑」。

| 要查什么 | 直接读取 |
|---|---|
| 某个实验跑在哪台机、花了多少、关没关机 | §1 总表对应行，再核该轮原始产物 |
| 读数能不能与历史比较 | §0 的列纪律 + [实验规则](<EXPERIMENT_RULES.md>) 的对照口径 |
| 这一轮的对照（基线）是谁 | [基线名单](<BASELINES.md>) 对应实验行与该轮 `plan.json` |
| 停机原因属于哪一类 | §2 停机分类词表 |
| 新记录该填哪些格、怎么写 | §8 维护纪律 + §1 的模板行 |

**行动前必读条件不变**：开机前读 [实验规则](<EXPERIMENT_RULES.md>) 与本表 §0；引用机器状态或数值前，**回读原始出处**。

⚠️ 本台账只登记**当前留存的运行**。历史轮次按时间移入[历史索引](<历史/INDEX.md>)；移走的行仍按编号可查。
⚠️ 本台账**不是**基线名单：基线「谁是谁的对照」写在 `BASELINES.md`；本表只记运行事实。

## 0 怎么读

| 列 | 含义 | 取值纪律 |
|---|---|---|
| **编号** | 实验号或运行标识 | ⚠️ **一行 = 一次运行**，不是一个实验号。同一编号跑多轮就多行，用「段/轮」区分。编号永不重用 |
| **机器** | 机名 + 容器 UUID + 机型 | ⚠️ 日志里 `machine=` 常是**调用方传进去的声明值**，不等于进程实际所在；两者不同必须分列注明。UUID 以 `list` 的落盘件或容器内 hostname 为准 |
| **题单 · 实跑** | 题单文件名 · 声明题数 · 实际跑完题数 | M 是**实跑**题数，不是题单声明数；两者不同必须写出来 |
| **读数** | 有效读数 / 无效读数 | 取原始逐题产物**自己数**，⛔ 不抄报告转述。判无效的依据（闸判词、缺失件、污染）必须同一行写出 |
| **停机分类** | 见 §2 词表 | 必须落到词表里的某一类；证据不足就写「未判」并列出缺什么，⛔ 不要凑一个 |
| **花费【推断】** | 机时 × 单价 | ⛔ 无账单读数时一律标【推断】并写算式；单价来源要写出；成本未知就保留「未知」 |
| **关机** | `[OFF]` / 未确认 / 未关 | 「确认」= 有回读证据（`status=shutdown` 或落盘件）；机器没响应**不等于**已停 |
| **结果文档** | 仓库相对路径 | 写**原始产物目录**与判读件；指向报告时同时给报告路径与原始件路径 |

**证据等级**（与 [实验规则](<EXPERIMENT_RULES.md>) 同一套）：【实测】/【读码】/【推断】/【未验证】。**未标等级 = 未验证。**

**机器名的全局对照（必须现读，⛔ 不许抄表）**

> 判据：先列实例看哪台在跑，再取它的 `ssh -p` 与容器 UUID。表里只放**带实测时刻**的快照。
> 照表抄机名会**开错机且不报错**（开机成功、然后卡在找不到权重），所以每次开工前重读一遍。

| 机名 | 容器 UUID | 区域 | 机型 · 显存 | 单价及来源 | 实测时刻 |
|---|---|---|---|---|---|
| `<机名>`（占位） | `<uuid>`（占位） | `<区域>` | `<机型 · 显存>` | `<单价>` · `<来源文件或命令>` | `<YYYY-MM-DD HH:MM>` |
| `<机名>`（占位） | `<uuid>`（占位） | `<区域>` | `<机型 · 显存>` | `<单价>` · `<来源>` | `<YYYY-MM-DD HH:MM>` |

⚠️ GPU UUID 不能当机名判据：同一台机不同次可能给出不同 UUID。
⚠️ 从没承载过实验的机器要单独标「未承载过」——换过去不是换一台机，是新一轮搭环境（另一个区、数据与模型要重传）。

|---|---|---|---|---|---|---|---|---|---|
| `<n>` | `<exp-NNN>` 段`<i>`/`<k>`（`<臂名>`） | `<MM-DD HH:MM>`–`<MM-DD HH:MM>` | `<机名>`（`<uuid>` · `<机型>` · `<档位>`） | `<题单文件>` · 声明 `<N>` · 实跑 `<M>` | 有效 `<a>` / 无效 `<b>`（判无效依据：`<闸判词或缺失件>`） | `<正常收口 / 装置侧中断：逐字错误码>` | `≈¥<x>`（`<机时 h>` × `<单价>`，`<来源>`） | `<[OFF] / 未确认 / 未关>`（`<回读证据>`） | `<state/<exp>/runs/<臂>/ >` · `<判读件>` |

**加行时必须同批写清的四件事**（缺一条，这一行读数不许进任何结论）：

1. **实跑题数**与题单声明数是否一致；不一致就写缺哪几题、为什么。
2. **读数口径**：有效/无效怎么分、无效是因为漏题、污染还是闸判。
3. **代价**：机时、花费（标推断）、撞墙题数、空补丁题数（有则写，无则写 0）。
4. **对照**：这一行相对哪一行比较、两者差在哪一处改动；没有可比对象就写「单臂，只作并列」。

## 2 停机分类词表

| 分类 | 判据 | 记录要求 |
|---|---|---|
| 正常收口 | 驱动脚本给出收口行，逐题行数齐 | 记收口行的逐字判词与行数 |
| 装置侧中断 | 启动或运行时被装置自身切断（超时、断言失败、缺件、预算守卫） | 记退出码、已用时、逐字错误码，以及**没拿到几行** |
| 被外部切断 | 平台侧原因（余额、回收、被他人关机） | 记平台原话与发生时刻 |
| 未起跑 | 一行读数都没有 | 写清卡在哪一步；⛔ 不许把「未起跑」写成「失败」 |
| 未判 | 证据不足以下分类 | 保留原样并列出缺什么证据 |

## 8 怎么维护这份台账

| 什么时候 | 做什么 |
|---|---|
| 每轮实验**收工后** | 往 §1 加一行；当天补不齐就留「未取回」并写缺什么 |
| 每轮实验**开机前** | 读 §0 的机器现读判据，确认本轮机器与对照轮是否同一台；不同机 ⇒ 历史读数**不进判据** |
| 发现新矛盾 | 加一行并给判据与逐字出处；⛔ 不许只写结论 |
| 改动本文件 | 先存改前件，再改；更新头部 `LAST-EDIT`，`CUMULATIVE-DELTA` 记改了什么 |

**取数纪律**（不要读错）：

1. **编号 → 提交对象**取版本库现读，⛔ 不取任何冻结清单里的抄写值。
2. **工作区 → 标签**用 `git describe --tags --exact-match HEAD` 现读，⛔ 不用目录名反推。
3. **读数取原始产物**：逐题结果文件自己数，⛔ 不抄报告里的转述数字。
4. **机器取容器 UUID**：实例列表的落盘件或容器内 hostname。
5. **读远端日志一律先判编码**：这类日志常是 UTF-16LE，按 BOM 猜；判错会把正常日志读成乱码并误报失败。

# 实验规则（唯一住所）

> 评价实验、设计下一轮、启动测量前**整份读完本文件**；⛔ 不得只读节选或用别的摘要代替。
> 本文件规定实验专属纪律。授权、安全和现行用户裁定优先。机器、费用与读数留在各自台账，不在规则里复制。
> 证据等级：`【实测】`/`【读码】`/`【推断】`/`【未验证】`；未标等级 = 未验证。

## 0 一句话

**先把「要回答什么」和「怎样就算回答了」写死，再花机时。** 其它规则都是这一句的展开。

## 1 开工前的研究要求

### 1.1 预期先写，再开机

开机前把本轮预期写进[工作日志](<EXPERIMENT_LOG.md>)的新节；⛔ 不许先看读数再补写预期。
只在「接机自检必须先开机」这类情形下允许同段开机，此时必须写明偏差与影响评估，并保证预期段**不引用本轮读数**。

### 1.2 一次实验改「一个假设下的整组改动」

改动分三类：①测量装置 ②提交包 ③agent 策略。一轮**只动一类**；动了同类里的多处，必须能说清这一组属于同一个假设。
⛔ 混了两类 ⇒ 直接写「无法分别归因」，不许事后挑一个说成因果。
⛔ 「顺手一起改」不是理由：真需要一起改，就把它拆成两轮，或用同一轮的多臂对照。

### 1.3 每条预期必须带判据

判据写清观察量、取数路径、适用条件和解释边界。探索性实验默认不设数字门槛，可以形成有证据的条件化结论。确认性实验另写阈值和理由。criteria.source可选，不强制背书原文。无法测量时先补装置，不把无读数写成已验证。

### 1.4 结论被推翻时，不覆盖旧结论

旧结论原文保留，用更正栏（原说法 → 修正后 → 证据）指回原条目。⛔ 不许把「已推翻」的结论悄悄改成新结论。

### 1.5 题单里三类对照都要有

| 类别 | 定义 | 缺了会怎样 | 最小规模 |
|---|---|---|---|
| 目标题target | 直接检验本轮假设的样本 | 无法回答本轮问题 | 非空，按问题的信息量选择 |
| 回归题regression | 适用装置下历史通过、需守住的样本 | 无法判断是否做坏旧能力 | 覆盖声明的previous_passes，目标与回归不重叠 |
| 本该失败的题 | 本轮改动**理论上碰不到**、历史必失败的题 | 无法分辨「整体变差」与「这批题本来就难」 | 0–1 道（可不设） |

⚠️ **对照题不可裁**：裁题前先问「这题是不是某个判据的唯一来源」；是就按判据保留，不按「能不能过」保留。
⚠️ **题数按信息量裁，不按对称性裁**：不产生本轮那个观察量的题一律不进题单。

#### 1.5.1 对照取「同条件下的最好读数」，不要求每轮重跑基线臂

有同装置、同题单、同档位的历史读数时，可作对照，必须在台账写明那一条读数的出处与条件。
条件任一不同（机器、档位、题单、包体）⇒ **只能并列，不能作因果对照**；要判因果就同轮跑基线臂。

#### 1.5.2 永久剔除的题

被判定为「永远不做」的题单独列表，写明裁定原话与日期；⛔ 不许把「这轮没跑」写成「永久剔除」。

### 1.6 冻结这次要交上去的产物

两条并列的路，选一条并写清：①按文件清单逐文件记指纹；②对整包记指纹。**冻结件与跑的东西必须逐字节同源**。
⛔ 不许在起跑后改包再说「就是这一份」；⛔ 不许用目录名当版本判据。
冻结时同时记：题单指纹、配置指纹、驱动脚本指纹、版本标签。

### 1.7 只在代码副本里跑

远端只跑**检出副本**，⛔ 不在共享母本上直接改。副本路径、来源提交、检出时刻都要落盘。
理由：一次跑坏会把共享母本变成「没人说得清哪一版」的状态，而这类损坏**不报错**。

### 1.8 成本与「读数算不算有效」并列

成本 = **机时** + **迭代速度**（一轮从开机到拿到有效读数要多久）。
同样能回答两条设计时，选便宜的那条；读数无效就要重跑，重跑比并行省下的时间更贵。
先判断设计能否回答问题，再在同样有效的设计中比较机时和迭代速度。不用便宜但无效的测量代替研究。

### 1.9 预期必须附「结果分支表」

起跑前写死 2–4 个分支，每支写明：**读数形态** → **下一步动作**。
收工按实际读数落一支；⛔ 不许临场加一支「灰区」而不写判据（要留灰区就写清区间与「只记不判」）。

### 1.10 题单变更：先核批准范围，再冻结

增题、减题、换题要写变化、研究理由及新旧题单指纹。仍在现有授权与预算范围内时自主处理，超范围才请求批准。
⛔ 减题必须逐题写理由；⛔ 不许只写「为了省时间」。

### 1.11 自愈的窄例外与看门狗位置

允许脚本自愈的只有**单次、明确、可回滚**的环境问题（例如装包重试一次），⛔ 不许自愈「读数缺失」或「断言失败」。
看门狗只做两件事：**定时关机**与**在行数到齐后收口**；⛔ 不许改读数、不许替人判断结论。
看门狗必须留可核痕迹（启动时刻、期望行数、实际行数、触发原因）。

### 1.12 泄漏硬闸要移走**两条**路径

隔离区必须同时移走「答案母本」与「验收脚本可见的第二份拷贝」；只移一条会出现「看起来干净」的假绿。
⛔ 闸报出的「干净」必须能指到一次实际扫描的退出码；没有扫描记录的绿等于没判。

### 1.13 三方对账：清单 ↔ 磁盘 ↔ 调用方

三处必须对得上：**冻结清单**、**盘上实际文件**、**真正被调用的那份**。
⚠️ 「两份实现一致」单独抓不住问题（两边一起退回错路径时判据仍绿）⇒ 必须另有一条**行为判据**（跑一次并看输出）。

### 1.14 分阶段授权

| 规模 | 授权要求 |
|---|---|
| 小样本（冒烟、单题、抽样） | 在既有预算内可自主推进，但必须在预期段写明用了多少预算 |
| 大规模（多机、长时、整单） | 先把方案与预算写成可读的一页并发给用户，**等明确批准**再开机 |
| 平台提交 | **逐次批准**；⛔ 不许把「上次批过」当本次授权 |

⚠️ 独立审计通过**不等于**实验授权；授权、安全、执行真实性与重大研究缺陷才阻断研究，普通格式问题不发新审批。
⚠️ 研究报告失败不阻挡安全停止；机器未响应不等于已停；费用未知就保留「未知」与预留。

### 1.15 一轮实验的「人」是谁

每轮都要写清谁做决定：用户 / 主会话 / 编排者 / 执行者。同一轮里**决策人只有一个**。
⛔ 不许出现「以为有人在核、其实没人」的空位；派工按「角色 + 产物路径」两套坐标写，不用阶段编号代指职责。

### 1.16 事前设计的载体

设计方案要落成一份可机器读的最小件（选项、判据、预算、分支表），并有两端闸：**写的时候**校验必填字段，**跑之前**校验它与冻结件一致。
⛔ 设计只住在对话里 ⇒ 下一轮无法复核，且无法判「有没有按设计跑」。

### 1.17 方案审计

默认要审，三态结论：**可以推进** / **主会话小修自查后推进** / **重大问题暂不能推进**。
审计意见说明实质问题与研究影响。locator只作辅助，不强制每条意见定位字段。小修按审计契约自查登记，不占次数。执行参数、题单、实际实现字节等改变仍须复审。
⚠️ 审计通过不替代授权（见 1.14）；审计者不改读数、不写结论。

### 1.18 必读闸

主会话完整读取任务相关现行文件，保留实际工具返回的读取范围。请求了offset/limit不等于内容完整，截断时补齐。无需逐文件填写勾选表或读取时间。公共引擎尚未实现源框架完整逐行覆盖闸，不能以自述冒充宿主验证。

## 2 开工时

按顺序做，每步留痕：

1. 接机自检（机器、盘、依赖、模型在位），把结果写进日志节。
2. `--plan` 一类只读预检，确认路径、题单、配置齐全。
3. 单元件冒烟（一题或更小），确认装置能出读数。
4. 正式起跑；把启动参数逐字落盘。
5. 小样本后尽早核观察量和机制是否实际出现。无效测量先排错，再决定是否扩大规模。

## 3 收工时

1. 逐条回填「预期 vs 实际」，未达成的也留。
2. 读数**从原始产物自己数**；闸判词逐字抄；退出码逐字抄。
3. 记代价：机时、花费【推断】、撞墙题数、空补丁题数、缺件数。
4. 记边界：本轮不能回答什么。
5. 关机并留回读证据；没确认就写「未确认」。
6. 台账加行（运行登记 + 基线名单若有身份变化）；日志加节。
7. 新问题登记到工程未决清单，并给判据与出处。

## 4 什么不算「一次实验」

纯读文档、读码、维护与只做预检不能写成已运行评测。已经启动但装置失败、被外部中断或未取回的轮次仍保留实验ID和真实状态，只是不能得出研究结论。保留已有证据与缺件，不把未知终态改成失败或已停止。

## 5 收工自查（无需逐项交账）

- [ ] 预期段写在开机之前；或偏差已登记并说明不影响对账
- [ ] 唯一变量类只有一个；混了就写了「无法分别归因」
- [ ] 每条预期都有取数路径；每条都已回填实际
- [ ] 三类对照是否齐；减题是否逐题有理由
- [ ] 冻结件与跑的东西同源（指纹已记）
- [ ] 读数从原始产物数出；闸判词与退出码逐字记录
- [ ] 花费标【推断】并给算式；关机有回读证据
- [ ] 结果分支表落了一支；灰区有区间与判据
- [ ] 边界与不能回答的问题已写
- [ ] 台账、日志、未决清单三处都已更新
- [ ] 没有把「未跑」「未取回」写成「失败」或「已修」
- [ ] 未删除任何历史正文；更正走更正栏

# 预算与审批政策

> 一句话：**审批机制在核心里，用哪个通道是部署配置，不是默认。**
> 通道未配置时，小样本仍须在有效授权与预算内；扩大测试与线上提交等待真实审批链。

---

## 1 按执行范围决定审批

| 范围 | 所需证据 | 启动条件 |
|---|---|---|
| `small` | 已授权范围与有效共享预算预留 | 小样本机制验证自主推进；不是无限额度 |
| `large` | 同实验、同版本的明确批准 | 先成功送达 HTML 上下文，再送选择卡；两份回执均有效 |
| `submission` | 每次提交对应的明确批准 | 不用先前实验许可代替本次线上提交许可 |

治理层的通用 `off/required/verified` 状态不改变这三种执行范围。删策略、未配置通道、超时和没有回复均不能降低审批要求。关闭或豁免须核真实用户命令；执行者自述不算授权。

---

## 2 外部通道：默认关闭

| 规矩 | 理由 |
|---|---|
| **默认没有通道** | 核心不能在没配置时假设某个即时通讯工具存在 |
| 通道是**部署配置**，不是核心依赖 | 换部署就换通道 |
| **通道不可用 ⇒ 不发卡**（fail-closed） | 发出去收不到比不发更坏：人会以为在等 |
| **发卡前先查通道健康** | 不可用时默认不发；要硬发必须显式标记并把原因落账 |
| **没有回复 ≠ 批准** | 无回复、超时、通道坏都不构成同意 |

[决策服务](<../autoresearch/decisions.py>)负责 HTML 生成、同决策先页后卡、双回执、两小时取消及入向消费。通道由可信部署配置注入；发送成功必须有平台消息编号和原始回执，页存在或脚本返回零不能代替送达。

---

## 3 授权来源三档（⛔ 不许把一个写成另一个）

| 来源 | 载体 | 记录里写什么 |
|---|---|---|
| **可核事件** | 宿主确认过的入向事件 | `independence=verified` + 事件 id |
| **会话界面原话** | 用户在当前会话说的话 | `independence=declared` + 会话 id + 消息序号 + 逐字引文 |
| **政策级预批** | 「这类事不用每轮问我」 | `series_preapproved`（⛔ 不许写成 `user_approved`） |

⛔ **本地自述只能是 `declared`**。想变 `verified`，必须注入 verifier 去读宿主证据。
⛔ 不许自己给自己授权：执行方写下的「用户批准了」不是授权。

---

## 4 预算

| 规矩 | 判据 |
|---|---|
| 预算写在方案里（`plan.budget`） | `max_cost_units` ≥0 整数 · `max_seconds` >0 整数 |
| **不预填任何数值** | 未配置就是未配置；内核不提供隐藏默认值 |
| 花超了就停 | 停是安全动作，⛔ 不需要审批 |
| 扩额要人 | 扩额属于「需要人拍板」的那一类 |
| 一次授权跨轮**不许归零** | 轮数/额度计数原样继承；判不可用就**重新问人** |

⚠️ 预算单位（「cost_units」）是**部署方定义**的：可以是钱、可以是机时、可以是调用次数。
本仓库不假设单位，也不换算。

---

## 5 什么时候必须停

| 情形 | 动作 |
|---|---|
| 用户说停 | **立刻停**，优先于任何文档与审计动作 |
| 预算耗尽 | 停 |
| 故障 / 装置异常 | 停，并保留现场 |
| 审批缺失 | **不动**（不是「先跑再说」） |

⚠️ 「停机」永远不需要审批。任何契约都不许把停机写成需要批准的动作。

---

## 6 送达与判断边界

平台返回消息编号和通道回执才能记为送达；落盘不等于用户已读。没有真实通道验收时，必须明确标注仅离线验证。

## 7 审批页与方案集

审批 HTML 必须自包含，六块为背景、上下文、进展、方案集、待决定事项、证据索引；审查附录默认折叠。缺背景、上下文或进展时，先补材料，不生成空壳页。禁止外链脚本、样式与远程图片。

方案集顶层保留实验、目标、执行范围、问题族、基线、改动面、版本、推荐项、背景三段及面向人的阅读说明。每个选项保留下列 13 个字段；可空与未声明必须可区分。

| 字段 | 内容 |
|---|---|
| `id` | 唯一选项编号 |
| `what` | 用一句动词开头的话说做什么 |
| `fingerprint` | 参数或文件级抓手及前后变化 |
| `sweep_group` | 同参数取值扫描的组，可空 |
| `cost` | 机时、时长、任务数、机器数及可复算依据 |
| `criteria` | 探索性观察边界，或确认性量、门槛、出处与理由 |
| `tasklist` | 题单文件或显式题号，以及回归项重复安排 |
| `branches` | 支持、部分支持、未支持、装置失败各自信息与下一步 |
| `stop_point` | 本轮何时停止 |
| `not_doing` | 本轮排除什么 |
| `hypothesis` | 要验证的猜想 |
| `expected_pass` | 预期通过题号；必须显式声明，空数组合法 |
| `expected_effect` | 预期变化与量具解释范围；探索时可写观察及边界 |

探索性实验不强制数字阈值、效应量或固定重复次数。确认性阈值要有出处和理由；若以量具分辨率支持结论，须解释量具是否足够分辨预期差异。样本数与重复数须匹配解释范围，不为对称而多跑。

## 8 版本、短码与入向

批准绑定实际研究内容的规范化指纹；调用者抄写旧 `plan_sha256` 不证明当前内容获批。改预算账号与预留不改变已批准研究内容，但仍须重新通过共享额度检查。改方案、判据、题单、参数或说明内容须重新审批。

卡片按钮使用真实决策记录产生的结构化短码和选项，不从人读正文猜测。批准消费一次性短码；部分否决只否决对应选项，全否决与停止形成明确结论。请求发出两小时仍未批准则取消，迟到点击不构成批准。

文字入向落盘后仍须受管监听唤醒负责人；304 秒未回复按超期处理。回复引用同实验、同收件人的真实平台消息，缺入向映射不得无引用发送。卡片点击走执行或拒绝回执，不再创建文字回复任务。

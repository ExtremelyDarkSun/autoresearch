# 文档维护：分层、上限、滚动

> 一句话：**按「读的频次」分层，热件有硬上限，到线就滚成冷件，滚是搬运不是删除。**
> ⛔ 本文件只管「怎么摆」，不改任何文档的内容判据；冲突时以治理契约与上游规则为准。

---

## 1 十三条原则（P1–P13）

| # | 原则 | 一句话判据 |
|---|---|---|
| **P1** | 按**读的频次**分层，⛔ 不是按总大小 | 一份很大但一年读一次的不用切；要切的是「每次动它都得通读」的那份 |
| **P2** | 按**生命周期状态**切（未结案 / 已结案），⛔ 不是按主题 | 按主题切 ⇒ 想知道现状得读每一个主题 |
| **P3** | 冷件按**时间**切片（一天一份），⛔ 不是按主题 | 找某条先定位到哪天，再只读那一天 |
| **P4** | 热件必须有**硬上限**，到线就滚 | 没有上限的规则必然漂 |
| **P5** | 编号与节号**永不重用、永不重排**；冷件原样保留原号 | 删一条 = 标 `drop`，⛔ 不删块 |
| **P6** | 滚动 = **搬运 + 留痕**，⛔ 不是删除 | 冷件是证据，逐字不改；删除要用户同意 |
| **P7** | **双向指针** | 热件顶部写「已滚出到哪些冷件」；冷件顶部写「从哪份热件滚来 · 覆盖哪些编号 · 滚动时刻 · 滚动前热件 sha256」 |
| **P8** | 冷件必须有**索引**，且能按编号反查 | 没有索引的冷件等于丢失 |
| **P9** | 切割面只落在**已结案**上 | 「部分解决」「仍被引用」「有争议」的留在热件 |
| **P10** | 滚动必须在**没有其他写者**的窗口里做 | 并发滚动会丢别人的追加，而且不报错 |
| **P11** | 滚动前后各记一次**可核值**（字节数 + sha256），且算 hash 与最后一次写之间不许有别的写 | 做不到就别把 hash 写在同一份还会被写的文件里 |
| **P12** | 每条「必须滚」要么是**会红的闸**，要么只作**自查提示**；⛔ 不要求逐条交账 | 只写「应当定期滚动」等于不会滚；但「没逐条点名」不构成未完成 |
| **P13** | **渐进式披露**：先给当前答案，再给行动依据，最后按需读历史与原始证据 | 分层只决定阅读顺序和文件组织（§4）。相关现行文档仍须整份读，⛔ 不能用摘要或节选代替正文 |

## 2 判定：一份文档该不该分层

**前两条都满足才做，第三条决定切法：**

| # | 判据 | 怎么测 |
|---|---|---|
| **J1** | **它每轮 / 每次都被通读吗？** | 问：最近三次动它，是不是都得从头读一遍？是 ⇒ **候选（要切）** |
| **J2** | **它有明确的「结案」状态吗？**（已解决 / 已收工 / 已作废 / 已关闭） | 有 ⇒ 走 P2 的状态切法；**没有** ⇒ 走 P3 的纯时间切法（只留最近 N 天在热件） |
| **J3** | **它的增长是「追加新条目」还是「反复改旧条目」？** | 追加为主 ⇒ 时间切片成立；反复改旧条目为主 ⇒ 先给它加一个状态列，再切 |

⚠️ **判据方向（本条曾写反）**：**全读频次越高越该切**；「读者是同一批人」⛔ 不是免切理由。把「每次读全份」当成不用切，正好放过最该切的那一类（只增的台账就是这种形态）。

**⛔ 不该分层的情形（别乱切）：**

- 它是**索引**（`AGENTS.md` / `*_INDEX.md` / 仓库结构图）—— 索引的价值就在**一处看全**，切了就没用。
- 它是**一次性的报告**（`*_REPORT.md` / 分析文档）—— 写完就不动，**不是「经常需要编辑」**。
- 它的**读取入口本身就很少**（例如只在某条闸里被 `import`）。
- ⚠️ 它是**契约 / 规则正文** —— 冷热分层对它不成立（J2 要的「结案态」在规则上不存在，只有「生效 / 废止」，P2 的状态切与 P3 的时间切都没有落点）。⚠️ 但这**不等于规则正文不能切**，换一种切法，见 §3。

## 3 规则 / 契约正文怎么切（**≠ 台账的切法**）

| | 台账（只增的记录） | 规则 / 契约正文 |
|---|---|---|
| 切分的维度 | **状态**（未结案 / 已结案）+ **时间**（哪一天） | **触发条件**（「你正要做什么」→ 读哪一节） |
| 冷 / 热怎么分 | 热 = 未结案；冷 = 已结案按天 | **没有冷热**。切成「**入口表 + 若干按任务分的节**」 |

**两条硬约束（⛔ 这才是真限制，不是「不能切」）：**

1. **每节只有一份，⛔ 不许切出「精简副本」。** 两份必然漂，而且**不报错**：把未经核对的计数或结论抄进契约，契约与源头当场不一致。
2. **入口表 + 一跳可达。** 切开后，读 A 的人看不到 B，而 B 可能正是他必须守的 ⇒ 入口表必须把「**做什么 → 读哪节**」写死，⛔ 不许让他自己找。

⚠️ **切之前先查一件事：整份读是不是被「规矩」要求的。** 常见驱动是正文自己写着「动手之前先通读本文件」。⚠️ **但「改掉那句话」不是省成本的正当解法**：与任务相关的现行规则 / 方案 / 分析文档仍须整份读完。能省的只有「**不要把无关文档设成必读**」，⛔ 不是「把必读的降成节选」。⇒ 切分的问题从「砍掉整份读」转成「这份文档该不该进必读清单」。

## 4 渐进式披露：四层与读取条件（P13）

| 披露层 | 读者要回答什么 | 内容与读取条件 |
|---|---|---|
| **当前答案** | 现在以什么为准 | 先写口径、适用范围、已知缺口。**状态只在唯一正文维护**。 |
| **行动依据** | 现在怎么做 | 必读规则、前置条件、失败分支、验证命令。执行动作前必须读完对应内容。 |
| **历史变更** | 以前为什么不同 | 原文保留日期、编号和替代关系。只有追溯或冲突核查时读取。 |
| **原始证据** | 结论能否复核 | 直接定位日志、逐条结果、快照与命令输出。争议或验收时读取。 |

**披露不是省略。** ⛔ 禁止把安全约束、授权要求、适用条件或未结案事项藏进历史层。
**披露只组织文件，不豁免完整读。** 与任务相关的现行规则 / 方案 / 分析文档必须**整份读完**；⛔ 不得用入口摘要、节选或「必读条件」代替正文。披露层管的是「历史与原始证据什么时候去查」，⛔ 不是「现行正文可以只读一段」。
读者 ⛔ 不得靠通读变更史推导现状；入口用**直接链接**定位唯一正文，⛔ 不复制会漂的状态。

## 5 分层怎么摆（默认形态）

```
<热件>.md                       ← 只有「未结案」条目，有硬上限（§6）
<热件>_cold/                    ← 已结案，按天切片
   ├─ INDEX.md                  ← 唯一入口：编号 → 冷件文件名（按 P8 反查）
   ├─ 2026-10-13.md             ← 当天滚出来的所有节（逐字原文）
   └─ ...
```

**落点判据**：冷目录是热件的**同级子目录**，⛔ 不新建根级目录（宁可深一层，不要多一个根）。相对链接因此稳定，跟着热件一起搬家。
**命名判据**：`YYYY-MM-DD.md`。**同一天滚两次 ⇒ 追加到同一份**，⛔ 不建 `2026-10-13.2.md`；同日追加时在冷件内按滚动顺序加 `## 第 N 次滚动（HH:MM）` 小标题。
**⛔ 冷件不进 `archive/`**：`archive/` 的语义是「不用了但要留痕」，只收**整份退休**的件。冷件**还在被引用**（索引指着它、热件的结论指着它），性质不同。

**热件被切完之后长什么样**：

```markdown
<!-- 头部照常 -->
# <标题>

> ⚠️ **已结案的节已滚出本文件**（P6 / P9）：
> - `§1` – `§120` ⇒ `./<热件>_cold/`，索引在 [`INDEX.md`](./<热件>_cold/INDEX.md)
> - 本文件只保留**未结案**条目。
> - 滚动日志见 `./<热件>_cold/INDEX.md`。

（以下只有未结案的节）
```

## 6 上限与滚动的时机

**默认上限（本文件是这几个数的住所；可按文档在 `register_doc(limit_bytes=…)` 里改，改了写明理由并进 `CUMULATIVE-DELTA`）**：

| 量 | 触发线 | 硬上限 |
|---|---|---|
| 字节数 | **60,000 B** | **80,000 B** |
| 行数 | **400 行** | **600 行** |
| 未结案条目数 | **30 条** | **40 条** |

**取数理由**：60 KB 的中英混排约 2–3 万 token，是一个 agent 一轮里**敢通读**的量级；再大一个数量级就读一次吃掉半份上下文。
⚠️ **上限只算「滚进来的节」的字节合计，⛔ 不算常驻锚与头部。** **常驻锚**（例如「唯一真源」状态表）**必须留在热件**，它的大小不参与滚动判据。
⛔ **上限不是自动截断**：到线是**去滚**，不是丢尾部 —— 丢了就是静默失忆。

**滚动时机（三选一，先到先做）**：

1. 触到**触发线**时；
2. **一轮收工**时（无论有没有到线 —— 因为收工本来就要读写它）；
3. 有**明确的批量结案**时（一次把 10 条标成已解决）。

⛔ **不许在做别的事的过程中顺手滚**：P10 要求先确认没有别的写者，而「顺手」没有这个确认步骤。

---

## 7 滚动怎么做（照做八步）

1. **停写**：确认没有其他写者（P10）。
2. **量**：记下热件字节数与 sha256（P11）。
3. **选面**：只挑**已结案**的节（P9）。
4. **搬**：原样搬进冷件（按日期命名），逐字不改（P6）。
5. **写头**：冷件顶部写来源热件 · 覆盖编号 · 滚动时刻 · 滚动前热件 sha256（P7）。
6. **建索引**：索引表加行 `编号 → 冷件文件名`（P8）。
7. **回写指针**：热件顶部写「已滚出到 X」（P7），并按 §5 的模板落笔。
8. **重登记**：`register_doc(...)` 记新的热件版本；`roll_cold(...)` 记这次滚动。
   `doc_status()` 会列出超上限的热件与缺索引的冷件。

## 8 运行时读取测试（维护后必须实测）

用**新的只读 agent** 测实际读取路径，⛔ 不能靠「我读过」：

- 从项目入口找到当前答案，⛔ 不从聊天继承答案；
- 找到行动前必须读的规则及失败条件；
- 从当前入口直接打开历史依据与原始证据；
- 分清旧状态、当前状态与未登记状态；
- 记录实际工具读取路径、范围、答案与遗漏；
- 正向测试通过后，再测**错误入口或断链是否被识别**。

⚠️ **链接校验通过 ≠ agent 已读；agent 自述读过 ≠ 验证通过。**
维护报告要记录工具读取证据并列出未通过项；无法在隔离工作副本测试时，报告必须说明实际测试环境。

## 9 遗忘留给人工

**自主维护 ≠ 自主遗忘。** 框架可以补、可以改、可以更新当前状态；**不能自己决定哪段历史不重要，然后删掉或压缩掉**。
大规模压缩 · 结构重组 · 历史淘汰，**要用户同意或人在场**。
⚠️ **普通编辑前的改前归档不算一次审批** —— 两件事不同：**保留版本**（随时可做）与**主动遗忘**（要人）。

## 10 机械判据（`governance`）

| 规矩 | 谁拒 |
|---|---|
| 热件必须给上限 | `register_doc(tier="hot")` 缺 `limit_bytes` ⇒ 抛错 |
| 超上限可见 | `doc_status()["hot_over_limit"]` + `problems` |
| 滚动基线必须对 | `roll_cold` 的 `hot_sha_before` ≠ 最近登记哈希 ⇒ 拒 |
| 冷件不能与热件同路径 | `roll_cold` 拒（那是覆盖不是搬运） |
| 冷件必须带索引 | `roll_cold` 要求 `index_path` 非空；`doc_status()["cold_missing_index"]` |
| 谁滚的、滚之前是什么 | `gov_doc_rolls` append-only 一行 |

## 11 边界与交账方式

1. **「这次该不该滚」** 是人判断：脚本只知道字节与 sha，不知道条目结没结案。
2. **搬得对不对**：脚本不知道你搬走的是不是「已结案」。
3. **索引与冷件是否一致**：`doc_status` 只查索引路径非空，不查内容对不对。

⚠️ **不逐条交账**：以上三条是**自查提示**。只有**四类风险**才阻断并要求报告 —— **授权 · 安全 · 执行真实性 · 重大研究缺陷**。其余「某条纪律没做到」不构成未完成，⛔ 不要求每轮把清单逐条点名。

# 读取政策

> 一句话：**按角色读、按动作读、读过的会过期。**
> 目的只有一个：别用「读过的记忆」代替「现读的原文」。

---

## 1 公共底线（只有两样）

1. **入口文档 + 本仓库的硬约束**（谁都要读，读一次即可）。
2. **本角色的角色提示词**（如果这次确实以该角色被委派才有；主会话自己推进时没有角色包，
   ⛔ 不要求为了合规造一个）。

⛔ 公共底线**不包含**：全部台账、全部契约、全部角色文档。
⚠️ 没有角色包**不是**没读底线 —— 硬约束仍然要读。

---

## 2 按角色选文档（选中的整份读完）

| 角色 | 除公共底线外读什么 | 什么时候 |
|---|---|---|
| **researcher**（主会话） | 入口与「一轮应该长什么样」；本任务相关的整份现行文档 | 开局一次；每轮开工前 |
| **planner** | 方案契约 + 上一轮的读数与经验 | 派工后动手前 |
| **runner** | 运行与预算契约；本任务相关的整份现行文档 | 派工后动手前 |
| **scribe** | 现状页契约（八节）+ 人给的材料 | 派工后动手前 |
| **independent-reviewer** | 方案审计契约（三项重点 + 实质意见）+ 材料包 | 收到派工后**动手前**一次 |
| **intent-monitor**（仅用户显式启用后） | 意图监控契约 + 固定截止的会话原文 | 启用后的三类触发派工时 |
| **trajectory-reviewer** | 轨迹复盘契约（九节 + 输入清单） | 专题收尾时派工后 |

与任务相关的现行规则、方案、分析文档必须整份读完。摘要、节选、他人转述不算读取正文。归档、冷件和历史快照在追溯时按编号查证，不要求全仓库通读。已逐字内嵌全文且版本未变时，不重复读取。

---

## 3 什么时候重读（读过了不等于一直算读过）

| 情形 | 要求 |
|---|---|
| 同一会话的后续回合 | 只读**变化了的那一份**（现读，不靠记忆） |
| 版本变更（契约 / 角色提示词 / 方案被改过） | 重读受影响的正文；角色包哈希只保证生成那一刻一致 |
| 失忆 / 上下文被压缩 / 换会话 | 重读公共底线 + 本角色那一行；⛔ 不必重读全部历史 |
| 读到的是断链 / 打不开 | **不许猜着继续**：先报「缺件」，在受影响动作前补齐 |

---

## 4 按动作读（用到那一步才读，且不授新权限）

| 你正要做的动作 | 才去读 |
|---|---|
| 写方案 / 冻结 | `plan.md` + `plan_audit.md` |
| 开跑一次实验 | 审计状态（`audit_state`）；监控仅在用户显式启用后读取对应契约 |
| 结束一轮、写现状页 | `status_page.md` |
| 收尾专题 | `trajectory_review.md` + `research_lessons.md` |
| 改契约 / 改角色 / 改文档 | `doc_maintenance.md` + 本文 |

⛔ **读政策不授新权限。** 权限只来自用户的真实授权与现行契约；
「我读过那份文档」不构成任何许可。

---

## 5 派工只写三样

1. **链接**到本文；
2. **本次任务的范围与边界**；
3. **读者是谁** —— 一句话写明「这个人知道目标与结果，但不知道内部叫法」；
   给他看的第一段不许出现内部术语。

⛔ 不要把三样读法**逐字复制**进任务书（那会变成又一份政策副本）。
⛔ 角色包已内嵌提示词时，不再要求子 agent 重读同源文件。

---

## 6 证据与交付（不因省 token 放宽）

1. 结论要指到**原始命令、输出、退出码或原始文件**，不指转述。
2. 要核一条结论就现读原文、现跑命令；⛔ 不许用「摘要已经写了」挡住核查。
3. 交付写四样即可：**结果 · 证据 · 异常 · 未决**；⛔ 不整篇复述上游文档。
4. **隔离不因省 token 放宽**：新工单用新子会话；⛔ 不许为省 token 把两个工单塞一个会话。

---

## 7 机读清单

`kernel/contracts/reading_required.json` 是「谁在什么阶段必读哪份完整文档」的唯一机读住所。
每条含 `id` / `role` / `phase` / `path` / `scope=full_document` / `why`。旧anchor只作兼容标记，不缩短读取范围。

⚠️ 改必读项**只改这个文件**，并跑一次校验：
`python -m unittest discover -s tests -p 'test_governance.py'`（其中一条会查条目形状）。
⚠️ 清单里有条目 ≠ 有人读过：`record_read` 默认只能记 `declared`（见 `CONTRACT.md` I7）。

## 8 分层项目与独立短交接

项目组织路由与执行必读清单不同。项目 `context_routes.json` 指明动作范围、目录入口及共同正文；`reading_required.json` 仍定义执行角色与阶段的文档义务。入口存在不证明宿主自动注入。

主会话先读全局规则，再选任务相关现行文档并整份读完。子会话默认新建，不继承聊天，不主动遍历项目AGENTS与全部索引；主会话传递适用约束、指定输入与验收条件。指定规则或证据仍全文读取，不以任务摘要替代。

独立审计必须拿到真实方案、来源和原始证据，不得只以负责人结论摘要为输入。写页供料已逐字包含的同版本正文不重复读。不要同时加载与当前任务无关的角色包。

机器生成的AI_WORK仅提示阅读顺序，不是证据正文，也不豁免安全规则。历史包保留当时字节，新工单用现行版本；接续旧任务先核来源版本及政策。

压缩或换会话后，恢复当前任务输入、已知未决及动作授权，再恢复适用规则；不能只恢复角色名称。下一轮明确继承已知、未知、要改变什么、怎样判断，保留负结果与被推翻的判断。

## 9 读取路径的验证

组织维护后用新的只读会话从根入口查当前正文、行动前规则、历史与原始证据，区分现状与未登记状态。记录实际工具路径、读取范围、回答及遗漏；再用断链或旧快照做反向测试。
链接检查不等于实际读取，agent自述也不等于宿主已注入。报告列未通过项及实际测试环境，不把静态通过写成动态加载完成。

监控默认关闭、审计只抓三项重点。关闭时不要求初始化、逐条问意图或派监控，历史账不删除。执行边界与最新同步验证见[同步记录](<../../docs/FRAMEWORK_SYNC.md>)。

读取证明只认宿主可核返回。请求offset/limit覆盖文件，不表示正文实际返回完整。尾部截断、中间跳号、单行截断都不能声明整份已读；长文分小块补齐，过长单行先提供无截断视图。当前公共record_read核宿主来源与版本，尚未实现源闸的逐行覆盖判定，不能宣称其已自动识别全部截断。

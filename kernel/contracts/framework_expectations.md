# 框架行为预期：可复用验收基准

这份文件是源行为预期的**中性化改写**，不是逐字原件。保留 A–L 与 V1–V3 全部 109 个编号，以及下面的无编号要求。原件中的私人会话、机器、真实实验结果、历史台账与个人通道部署不公开；旧测试数字不作为新仓库验收证据。源文件字节摘要见[验收记录](<../../docs/EXPECTATIONS_ACCEPTANCE.md>)。

**这些是要求，不表示仓库已实现。** 每个编号的迁移现状与缺口见[逐项验收表](<../../docs/EXPECTATIONS_ACCEPTANCE.md>)。迁移验收必须查实际入口、依赖、失败路径、持久产物与测试，不能只看同名函数或契约文件。

## 适用范围与冲突处理

- 主会话直接推进是默认。派编排者和专门联络子会话不再必需；独立方案审计和 scribe 写研究页的要求仍有效。
- 旧固定终点闸及 C10/C11 不再是必跑条件；报告、证据、研究复盘和下一步动作仍须完成。保留历史工具需求不等于恢复已退役闸。
- 小样本机制验证在已授权范围内自主推进；扩大题单、批量比较和组合验收先送上下文 HTML 再等明确批准；线上提交逐次批准。生产通道由部署选择，配置可换但送达、来源与顺序要求不能删除。
- K6 的旧“一切 unknown 必须阻断”由后来 K13 修正：unknown 可以非阻断，但必须写为何；实质设计缺陷才阻断。K11 是历史豁免，不能称作审过。
- L6 源行同时残留“一轮一次”和早期 pending/evidence 两次触发文字。按最新一次口径，在分析完成后审一次；前后阶段状态仍需防遗漏，不恢复每阶段重复审查。
- 源表的设计、历史测试、当前实现是三种信息。源项目尚未实现的目标（例如 H8）仍保留为目标，不能标成迁移已完成，也不能擅自退役。

## 无编号要求的验收范围

| 来源 | 保留的要求 | 验收方式 |
|---|---|---|
| §0 时间线 | 先读现行要求和已知未决；准备事前材料、独立审计、授权预算、真实启动、保存结果、分析、scribe 研究页、交付、下一步；用户停止优先 | 从新工作区运行一轮并保留各步骤产物；有停止和失败负例 |
| §0 可选委派 | 仅启用时查真实父子谱系、结束与验收分离、禁止越级续接；局部中断不等于整树或远端停机 | 真实宿主谱系与产物验收；不靠角色包或列表快照代替 |
| §0.5 三层自动 | 分清代码自动、agent 主动发现并登记修复、人主动纠错；agent 自进化是主要通道 | 每条发现标证据等级，留原命令输出、改前证据与针对性验证；不得用必须全代码化缩小要求 |
| §0.6 迭代节奏 | 少量任务验机制、准备组合、审批大题单、冻结组合与对照做逐题配对；大题单运行时继续安全小样本或零 GPU 工作 | 分线实验记录；不抢机器卡、不超成本、不改正在跑的冻结包题单参数、不把并行结论塞进本轮、每线记起止；单机先保大题 |
| §8 成功形态 | 用户消息被接住、持续推进、叫停有效、问题修复留证、开工说清要验什么、审批前先收到上下文 | 实际入口端到端正负例；结构检查不能独自证明这些结果 |
| §9 差异处理 | 失败步骤停止，不停止其余已授权安全工作；先保留首错命令输出退出码，查重登记、定负责人、修复、复验后恢复；在途任务先核状态防重复派工 | 持久问题记录与冷件索引，原始输出、修复和验收关联；只聊天说明不等于问题关闭 |
| 专题与复盘 | 独立代码环境与落点，专题目标、假设、边界、路线、证据索引；实验前后主文档快照；轨迹复盘与经验确认版本绑定 | 登记和真实隔离分别核验；研究事实、流程状态和经验确认不混写 |
| §11/§12/§14 边界 | 生成供料或回执不等于真实会话执行或送达；强杀与绕过入口不能宣称被拦；记录是不可信数据，读文件指令不当命令执行 | 宿主和通道实测，明确旁路覆盖边界；角色读取次序与报告内容另验 |

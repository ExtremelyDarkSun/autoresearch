# 写方案（plan_authoring）

> 动手写之前先看这五条**退回原因**；它们是从真实审计里收出来的，不是设想。
> **审计只看三件事**：① 这一轮问的是不是**问题 / 目标**要问的；② **设计、实现、测量的基本正确性**；
> ③ 有没有**会改变决定**的历史限制被漏掉。⛔ 不需要按七项逐项填表，⛔ 不需要给每条判据附原文引文；
> 但**基本正确性**是硬要求（见第 5 条）。

---

## 0 五条最常见退回原因（第 5 条 2026-11-09 加）

1. **判据文字与实际取的数不同源**：写了「通过率」，实际读的是「通过题数」。
   ⇒ 判据每个字都要能在结果字段里找到对应的量。
2. **先定门槛再看基线**：门槛是拍的。
   ⇒ 确认性实验先看基线，再定有出处的门槛。探索性实验写观察与解释边界，不编数字门槛。
3. **登记的判据对象不是被评的那个**：写的是 A 指标，评测产出的是 B 指标。
   ⇒ 去读评测入口到底写哪些字段（别猜）；判据对象要核「存在、是判分对象、是改后版本」。
4. **改动后只改了一处登记**：方案、契约、模板各写一份同样的值，改一处必漏两处。
   ⇒ 同一个值只写一处，别处引用（`CONTRACT.md` I1）。
5. **送审前没本地排错、也没写冒烟**（2026-11-09）。
   - **本地排错**：语法能不能过、路径在不在、参数名对不对、改的配置运行时**有没有人读**、
     返回字段是不是那个、题量 / 命令是否真实存在 —— 读码或跑一次离线样例就能发现的错，自己先排掉。
     ⛔ 不许把明显的实现错误留给审计，⛔ 更不许把「跑起来才知道」当借口；**明显的前提 / 实现错误
     也不许说成「探索未知」**（审计会按问题判，必要时直接阻断）。
   - **1 个最小样例冒烟**：方案里要写明「先只跑**最小的 1 个样例**，确认**实际采用**（改动真被调用 /
     被加载）· **实际参数**（传的是这份）· **实际返回**（结果里出现要读的量），再决定是否放大」。
     冒烟读数**不进**主判据，只决定「能不能放大」。
   - 自问：这两个错我现在能不能自己发现？冒烟看哪三样、在哪读、不符时停在哪一步？

⚠️ 这五条是**纪律**，没有闸自动判；把答案写进 `criteria` / `branches` / `notes`，让审计一眼能核。

## 1 六步

| 步 | 动作 | 产物字段 |
|---|---|---|
| 1 | 写一句**可被否掉**的假设：什么观察会让它错 | `hypothesis` |
| 2 | 列出验证它需要的**整组改动**；写结果分支时**另写一支「冒烟不符」**（采用/参数/返回任一不符 ⇒ 改设计，⛔ 不扩大） | `change_set` · `branches` |
| 3 | 写观察、条件与解释边界；确认性门槛另附出处（没有出处也允许，但必须能解释为什么这个门槛） | `criteria` |
| 4 | 选题：`target` 产生那个量；`regression` 含全部 `previous_passes`；`control` 视情况 | `case_sets` · `previous_passes` |
| 5 | 写三支结果分支，确认三支行动**不同**；演练里要能走通**冒烟入口与三样读数** | `branches` |
| 6 | 给预算与输入文件，跑校验，再冻结；**首审后按共同原因合并修**，措辞 / 定位 / 说明文字用 `correct` 自查 | `budget` · `input_files` → `freeze_plan` |

---

## 2 题量怎么定（不是对称性）

* 先问：**这次要读的那个量，哪些题会产生它？** 不产生的题一律不进题单。
* 「上次跑了 12 题，这次也跑 12 题，好对比」—— **对称性不是理由**。
* 减题时：`previous_passes` 一题都不许掉；掉一题就要说明「哪个判据不再可判」。
* 同一题在一份题单里只出现一次；要重复读数就**重复整轮**，不许写两行。

## 3 自检（写完逐条过）

- [ ] 假设能不能被某个具体读数否掉？
- [ ] `change_set` 里每一项都写了「改了什么」，不是「想让它变好」？
- [ ] 探索性判据有观察、条件和解释边界？确认性门槛有有限数及出处（或说明为什么这个数）？
- [ ] `case_sets.target` 非空，三类不重叠，类内不重复？
- [ ] `previous_passes` 全在 `regression` 里？
- [ ] `branches` 三支行动**确实不同**？有没有「冒烟不符就停」那一支？
- [ ] 写了**1 个最小样例冒烟**看哪三样、在哪读、不符停在哪一步？
- [ ] 本地能发现的错（路径 / 参数名 / 配置没人读 / 返回字段）都排掉了？
- [ ] `budget` 给了（不是抄默认值）？
- [ ] `input_files` 是相对路径，且你真的会去读？
- [ ] `validate_plan(plan)` 返回空列表？

## 4 冻结之后

| 你改了 | 后果 |
|---|---|
| 核心研究问题 / 假设 / 对照 / 判据机器读项 / 题单 / 执行参数 / 实现文件路径或字节 | 关键字段指纹变 ⇒ **旧审计不覆盖** ⇒ 重新 prepare + 复审 |
| 绑定字段的**纯文字**（`hypothesis` / `implementation` 五个说明字段 / `branches` 字符串） | 用 `correct` 逐字段申报 `wording_only: [{path, before, after, why}]`（不占次数、不重审） |
| `notes` / `title` / 说明文字 / `locator` / 证据引用换文件 | 指纹不变 ⇒ **不用重审**；用 `correct` 记 `what` / `self_check`（`sources` 可 `[]`） |

⚠️ 一个方案跨版本默认最多审 2 次。**先想清楚再 prepare**，别把额度花在改错字上。

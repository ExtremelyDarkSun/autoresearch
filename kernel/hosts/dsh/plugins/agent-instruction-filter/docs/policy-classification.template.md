# 指令分类表 · 空白模板

> 用途：当你要给「子 agent 的注入裁剪」写一条**显式策略**时，先用这张表把每个文件、每一节的去留判一遍，
> 再把结论落进一份外置策略 JSON（`config.policyPath`），而不是直接改 `policy.mjs`。
> ⛔ **默认不需要填这张表**：出厂策略是 `mode: off` + `rules: []`（什么都不裁）。本模板只在「确实要裁」时用。
> ⚠️ 填完必须跑 `verify-real-policy.mjs` 在**真实文件**上按内容核一遍；表里的行号会漂，⛔ 不要拿行号当判据。

---

## 口径

| 判定 | 判据 |
|---|---|
| **有用** | 直接决定该角色**怎么做**：职责边界 · 写权限 · 审批/派工路径 · 判据与阈值 · 事前预期 · 来源口径 |
| **无用** | 读了零增量也不误导：说明性事实、目录索引、「事实在哪」的指针 |
| **有害** | ① 把历史失败/旧口径读数当**当前前提**；② 逼读者去读「本不该常驻读」的文档；③ 纯操作步骤/命令清单/格式规矩 —— 它们挤占指令预算，且到执行时才需要 |

- 「无用」与「有害③」的分界：纯「事实在哪」的索引 → 无用；**要照着执行**的步骤/命令/格式 → 有害③。
- 判定必须**分角色**给（同一段对不同角色可能不同）。插件只能分辨「子级 / 非子级」，**认不出角色** ⇒
  两角色判定冲突时一律取 **保留**（保守），并在这里记下冲突原因。
- 字节口径：整份用文件大小；逐段按 UTF-8 逐行累加。读数会漂，⛔ 不抄历史值。

| 落地 | 策略字段 |

| 摘若干单行 | `mode: 'filter'` + `dropLines: ['<行子串>']` |

## 填完之后

1. 把结论写成一份 JSON 策略（结构见 `policy.mjs` 头部注释），放在**部署侧**，不要提交进本目录。
2. `node measure.mjs --config <清单.json> --policy <策略.json>` 看逐文件 before/after。
3. `node verify-real-policy.mjs --config <清单.json> --policy <策略.json>` 按内容核；退出码 2 = 未执行，不是通过。
4. 把 `cordis.patch.yml` 的 `mode` 改成 `filter`、`policyPath` 指向那份策略，再走安装器装载。
